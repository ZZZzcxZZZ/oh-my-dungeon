# 统一战役交互、规则驱动构筑与 Actor Markdown 设计

**状态：** 已批准  
**范围：** D&D 2024；不包含战斗轮次与战斗自动化  
**目标版本：** 0.1

## 1. 目标

本轮收敛聊天身份、DM 快捷操作、内容阅读、角色创建规则和角色导入导出。
系统继续保持离线优先，战役聊天室使用服务端；本地资料正文不得上传。

核心原则：

- 同一个业务能力只有一个操作入口和一个验证实现。
- UI 与未来 Agent 调用相同的业务命令。
- 职业、子职业、法术和装备资格由资料包规则声明，不按名称硬编码。
- Markdown 是可读交换格式，规范化 JSON 是运行时事实源。
- 怪物、NPC 和玩家角色均可进入角色库、打开完整角色卡并编辑。

## 2. 消息身份封包

发送消息时必须显式提交身份封包：

```json
{
  "kind": "actor",
  "actorId": "campaign-actor-id"
}
```

允许的 `kind`：

- `narrator`：DM 旁白。
- `actor`：已保存的玩家角色、NPC、怪物或同伴。
- `temporary`：只存在于这一条消息的名字和头像快照。
- `ooc`：用户场外发言。

成员的 `speakerMode` 只保存输入栏默认选择，不再决定已提交消息的身份。服务端
校验调用者权限后，将显示名、头像、Actor ID、发言时 HP 和身份类型保存为不可变
消息快照。历史消息不得读取角色当前 HP 覆盖旧快照。

临时身份：

- 不创建 CampaignActor。
- 不出现在角色库、战役角色列表或身份历史中。
- 发送成功后清除；发送失败时保留草稿。
- 必须按普通角色消息渲染，不得按旁白渲染。

## 3. 统一战役命令

聊天头像面板与战役中心复用同一 `CampaignCommandCatalog`。命令定义包含：

- 稳定 command ID；
- Material 图标与本地化名称；
- capability；
- 当前上下文可用性；
- 输入草稿；
- 调用统一业务服务的方法。

本轮命令：

- 掷骰；
- 角色检定；
- 直接伤害/治疗；
- 给予物品；
- 添加状态；
- 打开角色卡；
- 切换身份；
- 查看资料；
- 创建线索或地点。

无权限或未实现命令不渲染。DM 命令产生结构化 GameEvent，并向当前战役会话发送
可追踪的系统消息。

## 4. Material 3 交互

### 4.1 聊天输入栏

输入栏使用稳定的单行主布局：

- 40 dp 当前身份头像；
- 40 dp 紧凑图标式“说/做”选择；
- 可伸缩输入框；
- 48 dp 发送按钮。

窄屏不得压缩文字或让控件重叠。扩展工具放入头像打开的可滚动 BottomSheet，
按“身份、角色、DM、战役”分组使用 ListTile，不使用拥挤网格。

### 4.2 内容筛选

主页只显示搜索、筛选按钮和可横向滚动的已选条件摘要。完整筛选放在可滚动
BottomSheet 中；长标签允许正常换行，触控目标不低于 48 dp。

### 4.3 统一浮动阅读器

战役档案和本地内容条目共用 `KnowledgeEntryPreview`：

- 窄屏使用接近全高 BottomSheet；
- 宽屏使用最大宽度 Dialog；
- 正文、结构化属性、标签、关系和附件共用渲染组件；
- 创建者或 DM 的编辑命令放在标题栏，普通成员只读。

## 5. 规则驱动角色创建

继续使用资料包 v2，不增加可执行脚本。职业名称不得参与资格判断。

职业和子职业通过 `rules.grants`、`rules.choices`、`rules.progression` 声明：

- 等级特性；
- 子职业选择；
- 熟练项；
- 法术选择；
- 法术位和职业资源；
- 起始装备方案；
- 自定义选项。

法术选择必须由 choice 提供：

- `minimum` 与 `maximum`；
- `optionTags` 或稳定 entryId 白名单；
- `maximumOptionLevel`；
- 等级对应的选择增量；
- `prepared`、`known` 或 `pact` 模式元数据。

装备步骤使用带价格、数量和详情入口的列表。资料声明初始金币或方案预算；界面
显示已选总价和预算差额，但允许超额选择。

未知规则字段必须无损保留并静默忽略。无规则声明的自定义职业仍可手工创建，但
界面必须明确标记“该资料未提供自动构筑规则”。

## 6. Actor 与模板

### 6.1 内容模板

资料库中的 `monster`、`npcTemplate` 和 `item` 是不可变模板。怪物模板至少包含：

- 体型、种类、阵营；
- AC；
- HP 平均值与骰式；
- 速度；
- 六项属性；
- 豁免、技能、抗性、免疫与易伤；
- 感官、语言、CR、熟练加值；
- 特质、动作、附赠动作、反应和传奇动作；
- 来源与稳定 entryId。

### 6.2 角色库 Actor

从模板创建时生成独立 Actor：

- 保存 `templateRef` 和模板 revision；
- 复制可编辑角色卡数据；
- HP、资源、状态、物品和自定义覆盖属于 Actor 实例；
- 后续模板升级不得覆盖用户编辑；
- 玩家角色、NPC、怪物和同伴共用角色库外壳，类型专属区块分别渲染。

本地 Actor 可以发布到战役；战役 Actor 的状态自动同步回绑定的本地 Actor。临时
消息身份不属于 Actor。

## 7. Actor Markdown v1

Markdown 头部使用 YAML，正文采用怪物图鉴式分区。示例：

```markdown
---
format: dnd-table-actor/v1
kind: monster
name: 丧尸
system: dnd5e-2024
templateRef: private-mm2024:monster/zombie
size: medium
creatureType: undead
alignment: neutral-evil
armorClass: 8
hitPoints:
  current: 15
  maximum: 15
  formula: 2d8+6
speed:
  walk: 20
abilities:
  str: 13
  dex: 6
  con: 16
  int: 3
  wis: 6
  cha: 5
challengeRating: 1/4
proficiencyBonus: 2
---

# 丧尸

中型亡灵，通常为中立邪恶

## 感官与语言

- 黑暗视觉：60 尺
- 被动察觉：8
- 语言：理解生前语言但无法说话

## 特质

### 不死坚韧

特质正文。

## 动作

### 重击

- 类型：近战武器攻击
- 命中：+3
- 触及：5 尺
- 伤害：1d8+1 钝击
```

规范要求：

- YAML 保存机器需要的结构化状态。
- Markdown 正文保存可读描述和有序能力区块。
- 导入先解析、校验并显示预览，再新建或覆盖 Actor。
- 导出必须包含当前编辑后的完整状态。
- 导入后的 Actor 必须能在角色库列表、角色详情、编辑器、战役发布和聊天身份中
  正常使用。
- 玩家角色与 NPC 使用相同格式，只是 `kind` 和可选区块不同。

## 8. 私有资料提取

本地 `DND.v2025.9.14.chm` 中的怪物图鉴与城主指南内容只生成
`private-imports/` 下的测试资料包：

- 怪物图鉴条目映射为 `monster` 模板；
- 城主指南魔法物品映射为 `item` 模板；
- 原始正文和图片不得提交；
- 提取器、schema 和不含商业正文的测试夹具可以提交；
- 构建私有测试版时可显式注入该资料包。

## 9. 旧接口清理

在新路径有覆盖测试后依次清理：

- 持久化 temporary Actor 路径；
- 重复的聊天工具与 DM 工具 UI；
- 战役档案独立详情渲染器；
- 按职业名称判断法术资格的策略；
- `CharacterCampaignBinding` 兼容端点与模型；
- 已被聊天事件替代的旧 CheckRequest 查询接口。

数据库迁移只移除确认无运行时引用的表。每一步必须有迁移和回归测试。

## 10. 验收

- 四种身份连续切换后，下一条消息均按所选身份渲染。
- 临时身份消息不会创建 Actor，且不会继承旁白样式。
- 聊天头像面板显示全部适用 DM 命令。
- 聊天输入栏在 360、600、1024 px 宽度无溢出和重叠。
- 战役档案与内容库使用同一浮动阅读体验。
- 筛选长文本不压缩，全部条件可读可点。
- 自定义职业不修改 Dart 代码即可声明法术、装备、特性和子职业。
- 装备列表显示价格；法术选择严格执行资料声明的上限。
- 怪物 Markdown 导入后出现在角色库，可查看、编辑、导出并发布到战役。
- 私有怪物和物品资料包通过 schema、引用和真实客户端导入测试。
- 全量 doctor 通过；浏览器完成桌面与移动端视觉验收。
