# D&D Beyond 产品分析与开源版模仿计划

更新时间：2026-07-10

## 1. 结论

本项目下一阶段应从“跑团辅助工具”升级为“开源自托管的 D&D Beyond-like 跑团平台”。模仿对象不是 D&D Beyond 的商标、美术资产、官方付费内容或闭源生态，而是它的信息架构、角色创建闭环、角色卡交互密度、资料库组织方式、DM 控场路径和线上跑团工作台。

我们的差异化重点：

- 自托管优先：每个团、社群或服务器管理员都能独立部署。
- 内容包开放：SRD、第三方内容、房规、玩家自建内容都通过统一内容包导入、启用、覆盖和导出。
- DM 跑团优先：角色卡不是孤立工具，必须服务于 Session、Encounter、CheckRequest、Game Log 和线上桌面。
- 多端 Flutter：移动端、桌面端、Web 端共享体验，但针对屏幕宽度做不同信息密度。

## 2. D&D Beyond 的产品骨架

### 2.1 全局结构

D&D Beyond 的产品不是单点功能，而是一个环：

1. 资料库提供规则、职业、法术、装备、怪物和冒险内容。
2. 角色创建器把资料库内容转成可玩的角色。
3. 数字角色卡承载 HP、装备、法术、熟练、动作、检定和升级。
4. 战役把 DM、玩家、角色、共享内容和邀请关系组织起来。
5. 遭遇和 Maps 把角色、怪物、先攻、日志和地图放到同一张线上桌面里。

官方角色卡页面强调：角色创建器会引导创建角色，数字角色卡会跟踪生命值、装备、法术和能力，并支持点击进行检定、豁免、攻击和伤害掷骰。来源：[D&D Character Sheets](https://www.dndbeyond.com/resources/1779-d-d-character-sheets)。

### 2.2 角色创建器

D&D Beyond 2026 年的 Quickbuilder 明确把“快速上手”放在第一位。官方设计文章提到 Quickbuilder 是改进角色创建体验的第一步，目标包括降低规则门槛、跨手机到 4K 屏幕可用、用标志性视觉而不是大段文本开场、提供默认选择但保留深度，并让 DM 控制战役可用规则。来源：[Behind the Screen: the new Quickbuilder and future](https://www.dndbeyond.com/posts/2135-behind-the-screen-the-new-quickbuilder-and-future)。

可模仿的结构：

- 首屏不是表单，而是“创建方式选择”：快速创建、标准创建、导入 JSON、复制已有角色。
- 快速创建只要求少数关键选择：规则集、职业、种族/物种、背景、等级、名字。
- 标准创建使用分步器：来源 -> 基础身份 -> 属性 -> 职业 -> 背景 -> 装备 -> 法术 -> 审核。
- 每步都要有“推荐默认值”和“展开高级设置”。
- 创建完成后立刻进入可玩的角色卡，而不是停在编辑表单。

### 2.3 数字角色卡

D&D Beyond 的角色卡价值不只是展示数据，而是让所有常用动作都可点击、可掷骰、可追踪。移动端商店描述也强调离线访问角色、内置骰子、技能检定、攻击、豁免、管理生命值、法术位、装备和熟练项。来源：[D&D Beyond on Google Play](https://play.google.com/store/apps/details?hl=en_US&id=com.fandom.playercompanion)。

可模仿的信息层级：

- 顶部身份区：角色名、等级、职业、种族、背景、所属战役。
- 常驻战斗摘要：AC、HP、先攻、速度、熟练加值、被动察觉。
- 属性区：六属性使用统一卡片，每张卡显示属性值、调整值、豁免熟练状态、点击掷骰。
- 高频标签页：动作、法术、装备、特性、详情、笔记。
- 每个可掷骰项目都显示骰式、修正值和可点击动作。
- 手动覆盖字段必须标记来源，避免自动计算和玩家自定义互相覆盖。

### 2.4 战役与内容来源

D&D Beyond 支持在角色卡设置里按 Sources 和 Partnered Content 控制可用内容，分类包括 homebrew、core、expanded、legacy、partnered 等。来源：[Enabling Content Categories for your Character Sheet](https://dndbeyond-support.wizards.com/hc/en-us/articles/7747201820948-Enabling-Content-Categories-for-your-Character-Sheet)。

开源版应进一步强化这点：

- 内容源不是硬编码开关，而是 ContentPackage + Ruleset + CampaignContentPolicy。
- DM 在战役级别决定可用来源。
- 玩家创建角色时只能默认看到战役允许的内容，但可以保留“本地草稿/未绑定战役”的自由创建模式。
- 所有内容包都支持导入、dry run 校验、版本信息、导出和禁用。

### 2.5 遭遇、Maps 和线上桌面

D&D Beyond 的 Encounters 提供遭遇创建、运行、保存、编辑和恢复。来源：[How to Build Encounters and Run Them on D&D Beyond](https://www.dndbeyond.com/posts/1135-tutorial-how-to-build-encounters-and-run-them-on-d)。

官方 Maps 支持在地图内运行战斗遭遇：从 tokens 自动填充战斗，追踪先攻，玩家可从角色卡掷先攻，结果进入 sidebar 和 Game Log，战斗中有回合顺序、下一回合、轮数、隐藏怪物、战斗中增删参战者。来源：[Combat Encounters on Maps](https://dndbeyond-support.wizards.com/hc/en-us/articles/46385529638164-Combat-Encounters-on-Maps)。

对我们最重要的启发：

- 跑团桌面应是“Session + Game Log + Encounter + Character Sheet Drawer”的组合，不应只是一页聊天。
- 地图是高价值目标，但不必一开始做完整 VTT。先做无地图的线上桌面，再把地图作为同一桌面的一个视图。
- DM 需要一个右侧/侧边控场栏：先攻、参战者 HP、状态、隐藏信息、下一回合。
- 玩家需要一个角色卡抽屉：不用离开桌面就能点技能、攻击、法术、物品。
- Game Log 是线上跑团可信度核心：掷骰、检定请求、HP 调整、回合推进、DM 暗骰都应落日志。

## 3. 像素级视觉与交互拆解

这里的“像素级”指产品布局、密度、层级和组件行为，不复制 D&D Beyond 的品牌、美术、商标和专有内容。

### 3.1 全局导航

D&D Beyond 的体验倾向于“上方全局导航 + 内容区”。Flutter 多端应采用：

- 手机：Material 3 NavigationBar，最多 5 个主入口。
- 平板/桌面：NavigationRail 或 NavigationDrawer，左侧持久导航。
- 顶部 AppBar：显示当前服务器、当前模式、账户入口、主要动作。
- DM 模式不应只是多几个按钮，而应改变默认入口和页面排序。

建议主入口：

- 首页：当前服务器、最近战役、最近角色、当前 Session。
- 角色：角色列表、角色创建、角色卡。
- 战役：加入/创建、成员、邀请、共享内容。
- 桌面：Session、聊天、骰子、检定、遭遇。
- 资料库：法术、装备、特性、怪物、内容包。
- 设置：服务器、偏好、规则显示、管理员设置。

手机底栏可压缩为：首页、角色、战役、桌面、更多。资料库和设置进入“更多”。

### 3.2 角色卡布局

角色卡应有明确的视觉等级：

- 第一屏必须能看到身份、HP、AC、先攻、速度、六属性。
- 角色状态用 Material 3 `FilledCard` / `OutlinedCard` / `InputChip` / `AssistChip` 表达。
- 属性卡固定尺寸，避免数值变化导致布局抖动。
- 高频动作使用图标按钮和紧凑列表，不用大面积说明文字。
- 标签页承载长内容：动作、法术、装备、特性、详情、笔记。
- 桌面端使用左右分栏：左侧角色摘要，右侧标签内容。
- 手机端使用垂直滚动：顶部摘要固定优先级，标签内容下沉。

### 3.3 创建角色布局

角色创建器不应是一个长表单。推荐：

- “快速创建”是主按钮。
- “标准创建”是次按钮。
- 快速创建采用少量卡片选择，允许随机生成。
- 标准创建采用 Stepper 或分段页面，每步保存草稿。
- 每步右上角有规则来源/战役来源提示。
- 最后一页是 Review，显示自动计算结果和未完成项。

### 3.4 桌面与控场

桌面页应从聊天页升级为工作台：

- 左/中主区域：Game Log 时间线。
- 右侧：当前遭遇/先攻/参战者。
- 底部或浮层：骰子输入与快捷动作。
- 玩家侧：角色卡抽屉、待响应检定、当前轮到谁。
- DM 侧：发起检定、暗骰、调整 HP、推进回合、隐藏/显示怪物。

## 4. 开源版模仿边界

必须做：

- 学习信息架构、用户路径、响应式布局和交互模式。
- 支持 SRD 与用户自建内容，不内置侵权官方内容。
- 所有导入内容标注来源、版本、授权和本地服务器范围。
- UI 采用 Material 3，不做 D&D Beyond 视觉复刻。

禁止做：

- 复制 D&D Beyond logo、商标、图标、美术、付费内容或专有文案。
- 让项目看起来像官方产品。
- 把官方非开放规则内容作为默认数据。
- 依赖 D&D Beyond 账户或 API。

## 5. 下一阶段版本方向

### v1.2：D&D Beyond-like 客户端骨架

目标：让 Flutter 客户端拥有成熟产品的信息架构，并让角色卡从“数据表单”升级为“可跑团角色卡”。

范围：

- 重新整理 MainShell：移动端底栏、桌面端 NavigationRail、统一 AppBar。
- 新增 Home/Dashboard：服务器、登录状态、最近角色、最近战役、当前 Session 的入口。
- 角色列表升级：更清晰的空状态、创建入口、绑定战役信息、HP/AC/等级摘要。
- 角色详情升级：顶部身份区、战斗摘要、六属性卡、动作/法术/装备/特性/详情/笔记标签。
- 设置页升级：服务器管理、显示偏好、规则偏好、DM/Player 模式、调试/连接状态分组。

不做：

- 不做完整地图 VTT。
- 不做完整自动升级规则。
- 不新增官方非开放内容。
- 不改变服务端核心 API，除非客户端需要明显缺口。

### v1.3：角色创建器

目标：提供 Quick Build 与 Standard Build 两条创建路径。

范围：

- Quick Build：职业、种族/物种、背景、等级、名字、战役来源。
- Standard Build：分步创建和草稿保存。
- 创建完成进入角色卡。
- 基于当前内容包的选择器。

### v1.4：资料库与内容源体验

目标：把 ContentPackage 做成真正可用的资料库体验。

范围：

- 资料库首页、类型筛选、搜索、详情页。
- 内容源开关。
- DM 战役级内容策略。
- 导入/导出向导。

### v1.5：线上跑团桌面

目标：将 Session 页升级为在线跑团工作台。

范围：

- Game Log 中心化。
- 角色卡抽屉。
- 检定请求面板。
- Encounter 侧栏。
- 掷骰快捷动作。

### v1.6：地图视图

目标：在桌面中加入轻量地图视图。

范围：

- 地图资源上传。
- Token 放置和移动。
- 简单图层。
- 与 Encounter 先攻和 Game Log 打通。

## 6. 当前立即执行建议

下一步直接做 v1.2。它不要求大改服务端，也不会引入版权风险，但会显著改变产品观感和使用路径。

验收标准：

- Web 端打开后不再像临时 demo，而是有明确首页、导航和当前服务器状态。
- 手机宽度下使用底栏，桌面宽度下使用侧边导航。
- 角色卡第一屏能完成跑团最常用查看：HP、AC、先攻、速度、属性、豁免、技能、装备、法术、笔记。
- 设置页有分组和可理解的偏好项。
- `flutter analyze` 和相关 widget/domain tests 通过。
