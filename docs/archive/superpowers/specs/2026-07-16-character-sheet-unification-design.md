# 0.1 角色卡信息架构统一设计

## 目标

在不增加规则范围的前提下，重整角色详情的信息层级，使高频战斗数据可快速扫描、职业资源拥有独立管理空间，并消除资料条目在角色卡与资料库中的重复渲染。

## 产品原则

- 总览只承载战斗中持续变化且需要立即操作的数据：HP、临时 HP、灵感、死亡豁免、休息和状态效果。
- 职业资源独立为「资源」标签，统一展示剩余次数、已用次数、恢复规则和编辑入口。
- 状态信息使用固定尺寸的响应式信息板，不再把数值、按钮和标签平铺成一条无结构的 Wrap。
- 法术、装备、特性继续从角色引用打开浮动资料阅读器，不改变用户当前角色卡上下文。
- 资料阅读器是唯一正文呈现组件。若摘要与正文首段相同，只显示一次。
- 所有运行时修改先更新角色详情页内的 CharacterSheet，再调用持久化回调，保证标签切换后数据一致。

## 页面结构

角色详情保留顶部紧凑身份摘要，并使用七个 Material 3 标签：

1. 总览：战斗状态、生命快改、休息、状态效果、属性与技能。
2. 动作：规则动作和自定义动作。
3. 法术：施法摘要、法术位、按戏法和环位分组的法术。
4. 装备：货币、已装备物品、背包。
5. 资源：职业及自定义次数资源。
6. 特性：规则授予和手动特性。
7. 角色资料：人物叙事资料与笔记。

旧设置值 `status` 继续映射到总览，避免破坏已有偏好；新增 `resources` 作为资源页的稳定标识。

## 总览交互

战斗状态采用响应式网格，每个信息板拥有稳定边界：

- HP：当前值、最大值、进度和常用增减入口。
- 临时 HP：当前值和增减入口。
- 灵感：明确的开关状态。
- 死亡豁免：成功与失败分别显示，并提供增加和重置操作。

生命快改保留任意数值伤害/治疗，避免只能逐点修改。状态效果先显示生效项，再提供搜索与建议；自定义状态沿用当前离线数据结构。

## 资源交互

资源页使用响应式面板展示每项资源。每项包含名称、`已用/最大` 文本、剩余次数、进度、恢复规则、消耗和恢复按钮；有角色保存能力时提供新增、编辑和删除。短休和长休仍位于总览，但通过统一运行时更新函数同步资源用量，因此切换到资源页会立即反映恢复结果。

## 资料阅读器

新增共享 `ContentEntryReader`：统一呈现摘要、元数据、正文和角色规则。正文进入渲染前移除与条目名称相同的首个标题，以及与摘要规范化后完全相同的首个段落。完整资料页可复用阅读器正文并在其后插入职业等级特性列表、收藏和笔记。

## 非目标

- 不新增 2014 规则支持。
- 不改变资料包格式或同步协议。
- 不新增资源自动推导规则。
- 不重写角色详情所有子面板或引入新的状态管理框架。

## 验收

- 职业资源不再出现在总览，且可从独立「资源」标签完整操作。
- 总览四个核心状态以格式化信息板显示，横竖屏均可自适应。
- 任意数值伤害、治疗、状态、休息和死亡豁免行为无回归。
- 摘要与正文首段相同的法术详情只显示一份文本。
- 角色卡浮层与资料库详情使用相同的正文去重逻辑。
- Flutter 相关测试、静态分析和 Web 构建通过。
