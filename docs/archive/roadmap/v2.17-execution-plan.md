# v2.17 Session 角色运行态事件样式执行记录

## 目标

把 v2.16 写入时间线的 `character_runtime` 消息从普通聊天气泡升级为独立事件样式。HP、状态、休息和死亡豁免变化是跑团事实记录，不应和玩家聊天或角色卡掷骰混在同一种视觉层级里。

## 已完成范围

- 消息模型：
  - `ChatMessage` 新增 `isCharacterRuntime` getter。
  - 仍沿用现有 `kind: character_runtime` 字符串，不改服务端协议。
- 时间线 UI：
  - `character_runtime` 消息显示为居中的 Material 3 事件卡。
  - 事件卡使用 `tertiaryContainer` / `onTertiaryContainer`。
  - 标题显示 `角色状态`，图标使用 `monitor_heart_outlined`。
  - 不显示普通聊天的 senderId，也不显示 `角色卡掷骰` 标签。
- 回归保持：
  - `roll` 消息继续显示 `角色卡掷骰`。
  - `system` 消息继续显示为居中斜体文本。
  - 普通聊天和 DM-only 消息样式不变。

## 测试覆盖

- `session_detail_page_test.dart`
  - Session 中从角色卡扣 HP 后，返回时间线可看到 `角色状态` 和 HP 摘要。
  - 同一条运行态事件不会显示 `角色卡掷骰`。
  - Session 详情页既有 4 个测试继续通过。

## 不做事项

- 不新增服务端 metadata 或结构化 JournalEntry。
- 不增加运行态事件过滤、折叠或撤销。
- 不改 ChatMessage API 请求体。

## 后续建议

- v2.18：服务端增加结构化 `character_runtime_update` metadata。
- v2.19：Session 时间线支持按类型筛选：聊天、掷骰、角色状态、系统。
- v2.20：DM 控场侧栏调整角色 HP/状态时复用同一事件卡样式。
