# 战役、角色与 Material 3 收敛设计

日期：2026-07-30  
版本：0.1

## 1. 目标

本轮在保留现有 Flutter、NestJS、Drift、Prisma 架构的前提下，统一战役权限、角色发布与绑定、聊天身份、资料编辑、增量刷新和高频 UI 控件。

本轮不重写整个战役模块，不开发战斗系统，不引入通用 TRPG 规则引擎。

## 2. 核心原则

1. 服务端是权限最终裁决者，客户端可见性不是安全边界。
2. 相同行为只保留一套业务能力和一套共享控件。
3. 页面根据入口上下文自动补全已知信息，不重复询问。
4. 自动刷新只更新发生变化的数据，不重建整页。
5. Material 3 主题角色色、8dp 间距和标准组件优先于局部自定义样式。
6. 暂未实现或没有真实接口的入口不暴露给用户。

## 3. 战役身份与模式守卫

战役创建者是该战役唯一 DM 身份来源。其他成员均为玩家。

- 创建者只有在客户端全局 DM 模式下才能进入自己创建的战役。
- 其他成员只有在客户端全局玩家模式下才能进入战役。
- 两类限制复用同一个 `CampaignModeGuard`，使用相同提示结构和模式切换入口。
- 不在进入战役时静默切换全局模式。
- 客户端模式只决定界面入口；服务端仍根据成员角色判断权限。

## 4. 角色生命周期

### 4.1 状态

- `local`：只存在于本地角色库，未发布到战役。
- `published`：已发布到战役，但未必被成员绑定。
- `bound`：玩家在该战役中当前唯一绑定的玩家角色。
- `archived`：保留历史，不可发言、绑定或作为活动目标。
- `visibleToPlayers`：仅用于 NPC；默认 `false`，NPC 首次发言后自动变为 `true`。

`bound` 是成员与战役角色之间的关系，不替代角色自身的 `active/archived` 状态。

### 4.2 玩家流程

- 玩家模式创建本地玩家角色。
- 角色页不显示“发布到战役”按钮。
- 角色卡显示“所属战役”或“未绑定”状态。
- 玩家进入尚未绑定角色的战役时，从自己的本地玩家角色中选择。
- 客户端在一次业务操作中完成必要的发布与绑定，用户只理解为“绑定角色”。
- 玩家只能绑定自己拥有、未归档的玩家角色。

### 4.3 DM 流程

- DM 模式不创建玩家角色，只创建 NPC。
- DM 角色页创建时选择“仅本地”或目标战役。
- 从战役中心创建 NPC 时目标战役已知，不再询问用途。
- NPC 来源包括自定义空白角色和资料库怪物模板。
- DM 可完整编辑、归档、恢复和管理玩家角色，但不替玩家创建玩家角色。
- 一次性临时身份只属于一条消息，不保存到角色库。

## 5. 统一角色能力与组件

### 5.1 业务能力

`CampaignCharacterActions` 统一封装：

- 发布本地 NPC；
- 玩家角色发布并绑定；
- 编辑；
- 归档与恢复；
- 删除允许删除的本地角色；
- NPC 可见性；
- DM 管理玩家角色；
- 打开完整角色卡。

所有页面调用同一能力层，不直接拼装 API 调用。

### 5.2 共享组件

- `CampaignCharacterDirectory`：按未发布、战役和归档分组。
- `CampaignCharacterTile`：头像、名称、类型、战役、绑定、可见性和生命摘要。
- `CampaignCharacterActionMenu`：统一角色操作菜单。
- `CampaignCharacterPickerSheet`：带头像、搜索和分组的角色选择器。
- `DmNpcCreationFlow`：根据入口自动确定目标战役。

DM 角色页和战役中心角色页必须使用同一目录、条目和操作菜单。

## 6. 聊天身份与输入栏

### 6.1 身份信息条

- 头像、生命环、名称和摘要位于同一条信息条。
- 点击主体打开完整角色卡。
- 切换按钮位于信息条内部最右侧。
- 点击切换按钮打开角色/身份选择器。
- 临时身份与常驻角色使用一致的列表视觉。
- 删除“快速临时身份”下方额外说明。

### 6.2 输入模式

- 玩家角色、NPC、临时身份：显示“说 / 做”切换。
- DM 旁白：隐藏切换，固定发送旁白。
- 场外消息：隐藏切换，固定发送场外消息。
- 消息持久化明确的 `speakerType`，渲染不得依赖显示名称推断。

### 6.3 DM 快捷操作

给予物品、生命调整、状态给予和代骰都使用 `CampaignCharacterPickerSheet`，支持头像、搜索、玩家角色与 NPC。

物品、生命和状态变化以旁白消息样式记录，并同时产生结构化事件。

## 7. 即时刷新与同步

- WebSocket 只广播资源失效信号和必要游标。
- 消息变化只追加或更新消息列表。
- 角色变化只刷新角色缓存与对应角色条目。
- 资料变化只刷新资料列表或单条资料。
- 会话变化只更新会话目录。
- 保留滚动位置、输入草稿、展开状态和当前聊天。
- 前台恢复时使用游标补齐增量。
- 同类刷新请求合并，进行中的刷新不重复启动。
- 删除战役页顶部手动刷新按钮。
- 错误仅在对应区域显示重试，不替换整个页面。

## 8. 战役列表卡片

### 8.1 收起状态

显示战役图标、名称、主聊天室最后消息、时间和未读标记。展开按钮使用独立固定触摸区，不与时间重叠。

点击卡片除展开按钮外的区域直接进入主聊天室。

### 8.2 展开状态

- 主聊天室不再显示紫色置顶标签。
- 卡片主体本身就是主聊天室入口。
- 下方依次为可折叠的“小群”和“私聊”分组。
- 最底部仅保留“创建小群”和“发起私聊”。
- 删除重复成员头像列表。

## 9. 战役资料

- 所有战役成员都可创建资料条目。
- 玩家只能编辑和删除自己创建的条目。
- DM 可管理全部条目。
- 玩家与 DM 使用同一个添加入口、编辑器和详情阅读器。
- 标签位于标题下方。
- 关联条目使用可检索选择器。
- 详情使用与内容库相同的浮动阅读卡，不进入独立页面。
- 创建、更新与删除后只刷新受影响条目。

## 10. 投骰器

- 骰子数量、加值和 DC 使用可直接输入的数字字段。
- 骰面使用带图标的单选控件：d4、d6、d8、d10、d12、d20、d100。
- 即时显示组合表达式，例如 `3d8+5`。
- 代骰目标是战役角色或 NPC，不是玩家账号。
- 合并重复的“代骰检定”和“快速检定”入口。
- DC 在结果区域居中呈现，使用 Material 3 语义容器。

## 11. 内容库与响应式渲染

### 11.1 搜索与筛选

- 搜索框内部放置筛选按钮和已选数量。
- 详细筛选使用标准底部面板。
- 选中筛选使用 `secondaryContainer` 或其他主题角色色，不使用固定红色。
- 芯片、统计字段和长文本均允许换行。

### 11.2 表格与职业内容

- 宽表可横向滚动，但页面本身不得横向溢出。
- 紧凑屏优先显示等级摘要行。
- 职业等级表只显示结构化摘要。
- 详细职业特性由可点击条目展示，避免表格和正文重复。
- 提取失败的单元格不得作为超长标题或单行字段渲染。

### 11.3 怪物内容

怪物类型只使用标准大类。细分描述作为标签或特性。

结构化字段：

- `description`
- `traits`
- `actions`
- `bonusActions`
- `reactions`
- `legendaryActions`
- `spellcasting`
- `senses`
- `languages`
- `challenge`

映射到角色卡：

- `traits` 进入“特性”栏。
- 动作、附赠动作、反应、传奇动作和施法进入“动作”栏下的独立分组。
- 每项保留名称、正文、攻击信息、伤害表达式、次数和恢复规则。
- 怪物资料摘要位于角色卡最后。

导入器禁止把整段 HTML 或多项内容塞入单个动作字段。无法可靠识别的内容进入人工复核报告，不能静默合并。

## 12. Markdown 与扩展模型

Markdown 是人类可读的导入导出和镜像格式，结构化模型仍是运行时事实来源。

怪物/NPC Markdown 必须能无损表达第 11.3 节字段。解析后生成普通 `Character`，可在角色库展示、编辑、发布和用于聊天。

### 12.1 怪物 Character Markdown v2

运行时统一保存在 `Character.data.monster`，不得另建只读怪物卡模型：

```json
{
  "description": "正文描述",
  "traits": [],
  "actions": [],
  "bonusActions": [],
  "reactions": [],
  "legendaryActions": [],
  "spellcasting": [],
  "senses": ["黑暗视觉 60 尺"],
  "languages": ["通用语"],
  "challenge": {"rating": "5", "proficiencyBonus": 3}
}
```

六类能力条目共用 `{id, name, description}` 基础字段，并可增加
`attack`、`damage`、`uses`、`cost`、`ability`、`saveDc`、
`attackBonus` 和 `spells`。正文固定使用 `## 特性 / 动作 / 附赠动作 /
反应 / 传奇动作 / 施法` 分组，每项使用 `### 名称`，随后写正文和可选的
“命中加值、触及、射程、伤害、次数、恢复、消耗、施法属性、豁免 DC、法术”
字段。“描述”独立成节；感官、语言和挑战等级集中在文件末尾的“怪物资料”。

导出器可用 `dnd:monster-entry` 与 `dnd:monster-data` HTML 注释保存稳定 ID
和未显示扩展字段。重新导入时，人类可见字段优先于注释中的旧值，因此直接编辑
Markdown 会实际更新角色；注释不得成为覆盖用户正文的第二事实源。

怪物类型 `creatureType` 只接受 D&D 标准大类。原始“亡灵法师”“龙裔人形”
等细分描述进入 `classification.tags`。未知类型、未知章节、一个段落包含多个
标题等不可靠提取结果必须写入 `manual-review.json`，不得静默塞进名称或单个
动作字段。模板投影后仍生成普通可编辑角色，并同时提供上述结构化分组与现有
角色卡动作投影。

扩展制作器未来复用同一结构化 schema；本轮只固定 schema 和 codec，不实现完整制作器。

## 13. 设置页

主设置页顺序：

1. 服务器与账号
2. 角色模式
3. 外观
4. 跑团体验
5. 内容与本地数据
6. 关于

服务器与账号在主页面只显示当前服务器、连接状态、账号头像和用户名。服务器列表、备注、登录、自动登录与同步进入二级页面。

## 14. Material 3 共享控件

统一或新增：

- `AppSearchBar`
- `AppFilterSheet`
- `CampaignCharacterPickerSheet`
- `CampaignCharacterActionMenu`
- `ContentReaderSheet`
- `NumericInputField`
- `EmptyState`
- `InlineError`
- `SectionHeader`

要求：

- 使用主题语义色，不硬编码状态无关颜色。
- 采用 8dp 间距网格。
- 图标按钮具备至少 48dp 触摸区域和 tooltip。
- 固定格式控件使用稳定约束，动态内容不得推动布局跳动。
- 文本默认允许换行，必要时使用 `Expanded`/`Flexible`。
- 手机、横屏、桌面分别适配，不按视口宽度缩放字体。

## 15. 清理边界

- 删除重复的角色选择器、角色操作菜单、筛选条和资料阅读器。
- 删除无服务端能力支撑的 UI。
- 删除被新能力层替代的页面内 API 拼装。
- 不删除仍被现有数据迁移或兼容读取使用的旧字段；先标记弃用并提供迁移。

## 16. 验证

必须覆盖：

- DM/玩家模式守卫；
- 玩家绑定与自动发布；
- DM NPC 创建入口上下文；
- 角色页与战役中心操作一致；
- 资料作者权限；
- NPC 可见性与首次发言；
- 增量刷新不丢失滚动和草稿；
- 旁白/场外隐藏说做切换；
- 怪物动作分组解析；
- 长文本和窄屏无溢出；
- 投骰表达式与角色目标；
- Flutter analyze、客户端全量测试、服务端全量测试和私有 Web 构建。
