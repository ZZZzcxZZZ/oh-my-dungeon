# v2.16 Session 角色运行态日志执行记录

## 目标

把 v2.15 的 `角色状态写入日志` 偏好接入实际跑团桌面。玩家在 Session 中打开角色卡并调整 HP、临时 HP、灵感、状态或死亡豁免时，客户端应先保存角色运行态，再按偏好决定是否把摘要写入当前时间线。

## 已完成范围

- Session 角色卡抽屉：
  - `SessionDetailPage` 打开 `CharacterDetailPage` 时传入 `onUpdateRuntime`。
  - 当前 HP 变化调用 `CharacterController.updateCharacter`。
  - 临时 HP、灵感、状态条件和死亡豁免变化调用 `CharacterController.updateRuntimeState`。
- 跑团日志：
  - 当 `logCharacterRuntimeChanges == true` 且角色更新成功时，发送 `kind: character_runtime` 的消息。
  - 当前 HP 摘要格式：`角色名 当前 HP 旧值/上限 -> 新值/上限`。
  - 预留并实现了临时 HP、灵感、状态增删和死亡豁免摘要生成。
  - 当 `logCharacterRuntimeChanges == false` 时，只保存角色，不发送时间线消息。

## 测试覆盖

- `session_detail_page_test.dart`
  - Session 中打开角色卡，扣 1 点 HP 后会更新角色并发送 `character_runtime` 消息。
  - 关闭日志偏好后，同样的 HP 更新不发送消息。
  - 保持既有角色卡掷骰、默认骰子确认测试不回归。

## 不做事项

- 不新增服务端 `character_runtime_update` 结构化事件类型。
- 不新增 JournalEntry 字段或 Prisma schema。
- 不处理服务端权限差异；本版本沿用现有角色更新与消息发送 API。
- 不把普通角色详情页的运行态修改强制写入日志；只有 Session 入口具备当前场次上下文。

## 后续建议

- v2.17：把 `character_runtime` 消息在 UI 中做成独立的系统样式，而不是普通消息气泡。
- v2.18：服务端增加结构化 JournalEntry / ChatMessage metadata，记录字段、旧值、新值、操作者和可见性。
- v2.19：DM 战斗控场侧栏调整角色 HP/状态时复用同一日志摘要策略。
