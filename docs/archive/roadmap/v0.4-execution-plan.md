# v0.4 跑团桌面基础版 执行计划

更新时间：2026-07-09

## 版本目标

一场团能在线开始跑：DM 在 Campaign 下开启 Session，玩家进入同一会话，聊天与掷骰实时同步并落库，DM 可暗骰，Session 结束后可查看日志。

## 前置：UI 重构

v0.2/v0.3 客户端把账号、战役、房间堆叠在单个 `ListView` 里，嵌套深、难扩展。v0.4 要加入 Session/聊天/掷骰桌面，必须先重构导航骨架。

目标：引入 `ShellRoute` 式底部导航栏，每个 Tab 独立页面，遵循 Material Design。

## 验收标准

- DM 可以在 Campaign 下开启一次 Session。
- 玩家进入同一个 Session。
- 聊天实时同步。
- 掷骰实时同步并落库。
- DM 暗骰只有 DM 可见。
- Session 结束后能查看日志。
- 客户端有底部导航栏，各功能入口清晰。

## 不做事项

- 角色卡（v0.5）。
- 内容库（v0.6）。
- DM 控场/先攻/遭遇（v0.7）。
- 检定请求与快捷动作（v0.8）。
- 地图战棋、语音视频。

### 1. 数据模型

- `Session`：属于 Campaign，有 status（scheduled/active/ended）、startedAt/endedAt。
- `SessionMember`：Session 在线成员（含 role 快照）。
- `ChatMessage`：属于 Session，sender、kind（text/roll/system）、visibility（public/dm）、content。
- `DiceRoll`：属于 Session，character、notation、total、components、visibility（public/dm/blind）、createdAt。
- `JournalEntry`：属于 Session，type、summary、refId、createdAt。

### 2. 权限 Policy

- `SessionPolicy`：谁能开启/结束 Session，谁能查看暗骰。
- 复用 CampaignMember 角色。

### 3. Session API

- `POST /api/campaigns/:campaignId/sessions` 创建（DM/owner）。
- `POST /api/sessions/:id/start` / `POST /api/sessions/:id/end`。
- `GET /api/campaigns/:campaignId/sessions` 列表。
- `GET /api/sessions/:id` 详情（含成员、最近消息）。

### 4. ChatMessage API

- `GET /api/sessions/:id/messages`（分页，按权限过滤 dm-only）。
- `POST /api/sessions/:id/messages`（text）。

### 5. DiceRoll API

- `POST /api/sessions/:id/rolls`（notation、visibility）。
- `GET /api/sessions/:id/rolls`（按权限过滤）。
- 服务端解析表达式并落库，广播结果。

### 6. JournalEntry API

- `GET /api/sessions/:id/journal`。
- 系统自动写入：session_started、session_ended、roll、roll_critical。

### 7. WebSocket Gateway

- `ws /api/sessions/:id`（JWT 鉴权 + Campaign 成员校验）。
- 事件：`message:new`、`roll:new`、`session:updated`、`member:joined`、`member:left`。
- 暗骰只推给 DM/owner。

### 8. 客户端桌面 Tab

- 进入活跃 Session：聊天流 + 掷骰输入 + 在线成员。
- WebSocket 连接与断线重连基础版。
