# v0.5 角色卡基础版执行计划

状态：已完成

更新时间：2026-07-09

## 版本目标

玩家可以创建和维护一张可用于跑团的基础角色卡，并把角色绑定到战役。DM 可以在战役内查看角色，后续桌面、检定请求和遭遇系统都以该角色模型为入口。

## 边界

本版本做：
- 角色列表、创建、详情与基础编辑。
- D&D 5e 常用基础字段：等级、职业摘要、种族摘要、六属性、HP、AC、速度、先攻、技能、豁免、装备、货币、备注。
- 角色绑定战役。
- DM 查看战役内角色。
- HP 快速调整。
- 关键角色变更写入 JournalEntry。
- Flutter 客户端新增简洁的“角色”导航入口和基础表单。

本版本不做：
- 完整自动升级规则。
- 完整法术、装备、专长规则引用。
- 多规则系统完整角色卡渲染。
- 战斗遭遇、先攻队列和检定请求。

## 数据模型

### Character

角色归用户所有，不强制只属于一个战役。

核心字段：
- `id`
- `ownerUserId`
- `name`
- `avatarUrl`
- `system`
- `level`
- `classSummary`
- `raceSummary`
- `currentHp`
- `maxHp`
- `armorClass`
- `speed`
- `initiativeBonus`
- `abilities`
- `saves`
- `skills`
- `inventory`
- `currency`
- `notes`
- `data`
- `createdAt`
- `updatedAt`

`abilities`、`saves`、`skills`、`inventory`、`currency`、`data` 使用 JSON，以便 v0.6 内容库接入后继续扩展。

### CharacterCampaignBinding

角色通过绑定加入战役。

字段：
- `id`
- `campaignId`
- `characterId`
- `userId`
- `visibility`
- `status`
- `dmNotes`
- `joinedAt`
- `updatedAt`

约束：
- 同一个角色在同一个战役中只能有一个绑定。
- 创建绑定时，角色拥有者必须是该战役成员。

## API

### 角色 API

- `POST /api/characters`
  - 登录用户创建自己的角色。
  - 必填：`name`。
  - 可选：基础字段和 JSON 字段。

- `GET /api/characters`
  - 返回当前用户拥有的角色。

- `GET /api/characters/:id`
  - 角色拥有者可查看。
  - 战役 DM/owner 后续通过战役角色列表查看。

- `PATCH /api/characters/:id`
  - 角色拥有者可编辑基础字段。

### 战役绑定 API

- `POST /api/characters/:id/campaign-bindings`
  - 角色拥有者把角色绑定到自己已加入的战役。

- `GET /api/campaigns/:id/characters`
  - 战役成员可查看可见角色。
  - DM/owner 可查看该战役全部角色。

## 客户端

导航：
- 使用 Material 3 `NavigationBar`。
- 入口调整为：战役 / 角色 / 桌面 / 设置。
- Player/DM 模式仍在设置中切换，不把低频“加入”单独放到底栏。

角色页：
- 未登录：显示登录提示。
- 已登录：显示角色列表、创建按钮。
- 创建表单先覆盖名称、等级、职业、种族、HP、AC、速度。
- 详情页后续扩展为分区表单：概览 / 属性 / 装备 / 备注。

## 测试策略

- 服务端先写 e2e 测试，再实现 API。
- 角色权限用单元测试或 e2e 覆盖：
  - 未登录拒绝。
  - 用户只能编辑自己的角色。
  - 非战役成员不能绑定角色。
  - DM 可以查看战役角色。
- 客户端先写 API client 和 controller 测试，再接 UI。
- UI widget 测试覆盖导航入口和基础空状态。
