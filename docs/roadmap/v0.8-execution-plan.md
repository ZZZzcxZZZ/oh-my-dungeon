# v0.8 检定请求与快捷动作执行计划

状态：已完成
更新时间：2026-07-09

## 版本目标

让跑团桌面具备“DM 发起检定，玩家一键响应，结果进入聊天与日志”的基础闭环。v0.8 优先服务真实桌面流程：感知、调查、隐匿、豁免等常见检定可以快速发起、快速回应、快速查看结果。

## 边界

本版本做：

- Prisma 新增 `CheckRequest` / `CheckResponse`。
- DM/owner 可以在 Session 下发起检定请求。
- 检定请求支持全员、指定用户、指定角色三类目标。
- DC 支持公开和隐藏。
- 玩家可以对自己可见的请求提交一次响应。
- 服务端掷骰并落库，结果写入 `ChatMessage` 与 `JournalEntry`。
- DM/owner 可以查看全部响应状态和结果。
- 玩家可以查看自己的响应和公开结果。
- Flutter 在 Session 详情页提供检定请求列表、DM 发起入口和玩家响应按钮。
- 保留骰子历史沿用现有 `DiceRoll` / Journal，不新增复杂历史查询页。

本版本不做：

- 完整攻击命中、伤害、抗性、免疫、优势劣势自动判定。
- 复杂角色技能熟练自动计算。
- 自动从 D&D 规则内容推导技能数值。
- WebSocket 检定请求实时广播。
- 跨 Session 的全局骰子历史检索。

## 数据模型

### CheckRequest

- `id`
- `sessionId`
- `requestedBy`
- `label`
- `checkType`: `ability` / `skill` / `save` / `custom`
- `ability`
- `skill`
- `dc`
- `dcVisibility`: `public` / `hidden`
- `targetMode`: `all` / `users` / `characters`
- `targetUserIds`
- `targetCharacterIds`
- `status`: `open` / `closed`
- `createdAt`
- `updatedAt`

### CheckResponse

- `id`
- `requestId`
- `responderId`
- `characterId`
- `notation`
- `total`
- `components`
- `result`: `success` / `failure` / `unknown`
- `createdAt`

## API

- `POST /api/sessions/:id/check-requests`
- `GET /api/sessions/:id/check-requests`
- `POST /api/check-requests/:id/responses`
- `POST /api/check-requests/:id/close`

## Flutter 页面与状态

- `CheckRequestApiClient`：覆盖创建、列表、响应、关闭。
- `CheckRequestController`：挂在 Session 详情页，依赖 `AuthController` 和 `SessionController`。
- `SessionDetailPage` 新增简洁的检定区域：
  - DM/owner 可发起“感知检定”等请求。
  - Player 可看到待响应请求。
  - 点击响应后显示自己的结果。
  - DM 可看到提交数量与结果列表。
