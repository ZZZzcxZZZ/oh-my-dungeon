### 2.3 服务端构建 bug 修复（commits `1e57446`、`21e49ee`、`3d190b3`）

部署时发现运行时镜像无法启动，根因和修复如下：

1. **`INestApplication` 导入路径**：原代码使用 `import type { INestApplication } from '@nestjs/core'` 导致运行时找不到。改为从 `@nestjs/common` 直接导入（与 `ExceptionFilter` 等同源）。
2. **Prisma seed 改为纯 JS**：`prisma.config.ts` 原配置 `seed: 'ts-node prisma/seed.ts'`，但运行时镜像没有 `ts-node`（devDependency）。新增 `prisma/seed.js`（纯 JS，仅创建 `ServerSetting` 占位行），删除 `seed.ts`，配置改为 `seed: 'node prisma/seed.js'`。
3. **复制生成产物到 runtime 镜像**：runtime 阶段没有 `prisma generate` 步骤，导致 `@prisma/client` 不可用。在 Dockerfile 添加 `COPY --from=build /app/apps/server_nest/node_modules/.prisma ./node_modules/.prisma`。

> **下次构建服务端镜像时**：如果 prisma schema 有变更，确保 build 阶段先 `prisma generate`，再让 runtime 阶段 copy `.prisma` 产物。

## 3. 关键约束（不可违反）

### 3.1 项目级硬约束

- **版本号统一**：所有公开 commit 用 `0.1` 作为版本范围，例如 `feat(0.1): ...`。`v0.2`–`v2.x` 不得出现在新 commit。
- **战役是主入口**：战役 = 长期群聊 + 跑团工作区，不再要求逐层创建场次。
- **退役模块不得重建**：`RoomsModule`、`SessionsModule`、`SessionsGateway`、`CheckRequestsModule` 已删除，不得恢复路由或作为新功能的前置依赖。`Session`/`CheckRequest` Prisma 表暂留作预发布数据兼容，但不能作为新功能依赖。
- **商业规则正文不入库**：公开仓库、seed、客户端安装包不得包含 SRD/PHB 或任何官方规则正文。私人测试构建走 `scripts/build-private-test-apk.ps1` / `scripts/build_private_client.ps1`，构建产物不得分发。
- **离线优先**：未配置服务器时，资料库、角色、收藏、笔记、设置、规则计算和本地备份必须完整可用。服务器是可选同步设施，不作为本地功能门禁。
- **正文永不上传**：本地资料包正文与 assets 永不进入 Vault payload。Vault 只同步个人实体和资料包 manifest（`id/version/locale/system/contentHash`）。
- **战役只同步 DM 创建的独立 JSON 条目**：`CampaignContentEntry`、`CampaignActor` 通过 cursor 增量同步；WebSocket 仅广播 cursor + entityType，完整实体通过 HTTP changes 拉取。
- **不信任客户端身份**：聊天身份必须绑定 `CampaignActor`，服务端以 `campaignActorId` 为准，不接受客户端 displayName 作为权威。

### 3.2 客户端 UI 约束

- **Material 3 语义化颜色**：所有颜色必须用 `Theme.of(context).colorScheme`，不得硬编码。详见 `project_memory.md` 的颜色映射表（如 `surfaceContainerHigh` 用于横幅，`outlineVariant` 用于卡片描边）。
- **避免技术术语**：表单不得有 `slug` 输入（slug 由服务端生成）。详见 `project_memory.md` 的「foolproof design」条款。
- **底部导航**：成熟简洁的 Material 3 底部导航栏。
- **战役聊天页不得有三点菜单**：相关功能移到战役中心概览面板。
- **战役中心概览面板**必须包含「Campaign Settings」区块，DM 看到 4 项、普通玩家只看到「Leave Campaign」。
- **战役中心面板**必须包含邀请码列表和 DM 角色快速切换按钮（麦克风图标）。
- **3 个被禁用的工具栏项**（记录线索/分享地点/群文件）必须路由到预填充对应 `kind`（`clue`/`location`/`file`）的新档案创建表单。
- **角色创建/管理简化**：DM 无需绑定角色；DM 创建的角色支持快速切换。

### 3.3 数据与同步约束

- `CharacterContentRefs` 主键已从 `{characterId, slot}` 改为 `{characterId, entryKey}`（Prisma schema v8），避免多专长时的 UNIQUE 冲突。角色创建流程必须能从 v7 迁移到 v8。
- 角色创建必须有 `try/catch/finally`，防止 UI 按钮卡死，并提供详细错误信息。
- `CharacterController` 必须传播详细错误信息，不得返回通用消息。

### 3.4 部署约束

- 环境变量必须从 `.env` 读取，包括 `MAX_UPLOAD_SIZE_MB`。
- `DATABASE_URL` 用 `postgres` 主机名，不是 `localhost`。
- `POSTGRES_PASSWORD` 必须从 `.env` 注入，不得硬编码。
- Postgres 端口 `5432` 只暴露给 `127.0.0.1`。
- Docker runtime 镜像必须包含 `prisma.config.ts`。
- `prisma db seed` 必须在部署时执行。
- `start.sh` 必须在首次运行时生成随机 `POSTGRES_PASSWORD`，并处理 `.env` 创建。
- Docker 容器（postgres 和 server）必须有 `restart: unless-stopped` 策略。
