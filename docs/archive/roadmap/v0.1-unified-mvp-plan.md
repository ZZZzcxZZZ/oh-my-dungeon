# v0.1 统一 MVP 整合计划

## 状态

当前项目统一为 `0.1` 开发线。此前 `v0.2`、`v0.8`、`v1.0`、`v2.x` 记录全部降级为内部迭代日志，不代表项目已经达到可用 MVP。

## 0.1 产品目标

把已有工程能力整合成一个能开团使用的 D&D 跑团工具：

- 战役像 QQ 群聊一样作为主入口。
- 玩家进入战役后即可聊天、扮演发言、做动作、掷骰和打开角色卡。
- DM 工具、检定、资料库、遭遇和日志从战役聊天室的更多功能入口进入。
- 角色卡显示和运行态修改继续保留，但必须围绕战役上下文工作。
- 资料库必须有 GUI 新增/编辑/导入，不要求用户手写 JSON。

## 版本编号规则

- 当前对外版本固定为 `0.1.0`。
- 后续小步开发使用 `0.1` 内部计划编号，例如 `0.1-chat-01`，不再新增 `v2.x`。
- 历史文档保留用于追溯，但后续 agent 不应把历史版本当作已发布事实。

## 战役聊天室主线

### 战役列表

- 每个战役显示为一个群聊条目。
- 条目显示：
  - 战役名。
  - 当前用户身份：主持人、DM 或玩家。
  - 最近活动摘要。
  - 绑定角色头像/名字，后续从 `CharacterCampaignBinding` 读取。
  - 简要状态，例如 HP、AC、状态条件。

### 战役聊天室

- 点击战役直接进入聊天室，不要求先创建场次。
- 聊天室顶部显示战役名、成员入口、资料库入口和 DM 管理入口。
- 消息区支持：
  - 普通聊天气泡。
  - 角色动作事件，使用斜体或事件卡样式。
  - 掷骰结果。
  - 角色状态变更。
  - 系统事件。
- 输入栏支持：
  - `说` 模式：发送普通角色发言。
  - `做` 模式：发送动作描述，斜体显示。
  - `+` 更多功能：掷骰、角色卡、检定请求、资料库、上传/地图、DM 控场。

## 资料库主线

### GUI 管理

- 资料库页面应提供“新增内容”入口。
- DM 可选择内容类型：法术、装备、职业、种族/物种、专长、特性、怪物、状态。
- 每类内容先提供基础表单字段，复杂规则后续再结构化。
- JSON 导入保留为高级入口，不再作为唯一入口。

### 基础内容策略

- 开源仓库只能内置开放授权内容，例如 SRD / Creative Commons / 用户自建内容。
- 商业玩家手册 PDF 不应被批量提取正文并提交到仓库。
- 对于用户本地持有的 PDF，可以提供“私有导入器”：
  - 在本机读取 PDF。
  - 提取目录、名称、分类和页码等索引信息。
  - 生成私有内容包草稿，由用户在自己的服务器中保存。
  - 不默认导出或分发受版权保护正文。
- 具体边界见 [私有玩家手册导入边界](../content/private-phb-import-policy.md)。

## 首批 0.1 验收

- README 与执行状态文档都声明当前为 `0.1`，不再声称 v1.0/MVP 已完成。
- 战役页显示群聊式战役条目。
- 点击战役进入聊天室式页面。
- 聊天室提供 `说 / 做` 输入模式和 `+` 更多功能入口。
- `说` 消息以聊天气泡显示。
- `做` 消息以斜体动作显示。
- Player 模式不把“加入战役”作为底部常驻主按钮；DM 模式才显示“创建战役”主按钮。
- 聊天消息头显示绑定角色的简要状态。
- 资料库页面有 GUI 新增内容入口。
- 资料库页面有私有草稿导入入口，支持预览、dry-run 校验和导入到当前服务器。
- 文档说明玩家手册 PDF 的合法导入边界。
- `flutter analyze` 和客户端相关测试通过。

## 不做事项

- 不把商业玩家手册正文提交进仓库。
- 不在 0.1 首批实现完整地图 VTT。
- 不要求玩家先创建 Session 才能看到战役聊天室入口。
- 不继续扩展旧 `rooms` 原型。
