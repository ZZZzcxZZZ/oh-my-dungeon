# 玩家流程与战役工具收敛设计

**日期：** 2026-07-28  
**版本：** 0.1  
**状态：** 已确认  
**范围：** Flutter 客户端、现有 NestJS 战役/角色操作接口  
**不包含：** 战斗系统、通用 TRPG DSL、AI Agent 运行时、战役专属资料库

## 1. 目标

本轮采用“流程驱动收敛”方案，不重写现有角色、规则和战役模型：

- 角色创建只展示当前需要完成的选择；
- 规则选择有明确资格、数量和来源约束；
- 自定义内容始终可用，但与规则授予明确分层；
- 临时发言身份只属于单条消息，不创建持久 Actor；
- DM 高频操作从战役聊天直接完成并形成结构化事件；
- 暂未实现的功能不在界面中占位；
- 相关页面统一遵循 Flutter Material 3 组件、语义色和响应式布局。

## 2. 产品边界

### 2.1 三种身份

| 身份 | 是否持久化 | 是否有完整角色卡 | 用途 |
| --- | --- | --- | --- |
| 玩家角色 | 是 | 是 | 玩家长期角色与战役状态 |
| 常驻 NPC / 怪物 / 同伴 | 是 | 是 | DM 反复使用和管理 |
| 临时发言身份 | 否 | 否 | 单条消息使用一个临时名字 |

临时身份只保存在客户端输入草稿中。发送消息时提交
`speakerSnapshot.displayName`，服务端把快照固化到该消息；发送成功后客户端立即
清除草稿。它不得出现在角色目录、身份历史、Actor API 或同步数据中。

既有 `lifecycle=temporary` Actor 属于遗留数据：

- 客户端不再显示或创建；
- 服务端新建和更新接口不再接受 temporary；
- 数据库中的遗留记录保留以避免破坏历史引用，但统一视为 archived；
- 历史消息继续使用已经保存的 speaker snapshot，不回查临时 Actor。

### 2.2 资料来源

玩家创建角色时直接使用本地资料库，不再先选择“通用资料/战役资料”。

- 移除“选择创建资料”对话框；
- 不调用战役资料选择回调；
- 本轮不实现战役专属角色创建资料；
- 本地资料为空时提供明确空状态和“前往资料包设置”入口；
- 资料不足时只描述缺少的规则字段，不允许开放无限制规则选择作为回退。

## 3. 角色创建流程

固定主顺序：

1. 职业
2. 背景
3. 物种
4. 属性
5. 熟练
6. 装备
7. 法术
8. 故事
9. 审核

职业、背景和物种变化后重新计算规则授予和后续选择。已不再合法的选择自动移出
规则选择，但保留在页面内提示用户发生了什么。

### 3.1 两层选择模型

每个规则相关步骤分成两层：

- **规则选择：** 来自 `RuleChoiceDefinition`、progression 和稳定内容引用；
- **自定义：** 玩家主动添加的内容，写入 manual overrides，并标记为 custom。

规则引擎只验证规则选择。自定义内容不参与“是否满足规则选择数量”的计算，也不被
规则重算删除。

### 3.2 法术

规则法术候选必须同时满足：

- 条目类型为 spell；
- 属于当前职业法表；
- 法术环位不高于当前等级允许的最高环位；
- 满足 choice 的 optionIds、optionTags 和 maximumEntryLevel；
- 已选数量位于 choice 的 minimum 与 maximum 之间。

界面显示：

- 当前职业、施法属性和最高可选环位；
- “已选 N / 上限 M”；
- 环位、学派和名称搜索；
- 戏法与各环法术分组；
- 超出规则资格的原因；
- 独立的“添加自定义法术”命令。

规则法术达到上限后禁用其他规则候选，但允许取消已有选择。自定义法术始终可以
添加，并显示“自定义，不计入规则上限”。

### 3.3 装备与金币

装备步骤提供两种起点：

- 使用职业/背景提供的推荐装备包；
- 从本地装备和物品条目中自由选购。

页面将所有价格转换为铜币计算，再格式化为 pp/gp/ep/sp/cp 展示。需要显示：

- 建议金币上限；
- 已选装备总价；
- 剩余或超额金额；
- 每件装备单价、数量和小计。

金币上限只用于提示，绝不阻止超额选购、下一步或创建角色。超额时使用
`errorContainer/onErrorContainer` 提示，不使用阻断性错误。

玩家可以添加自定义装备，字段包括名称、数量、单价（可空）和备注：

- 有单价时参与总价；
- 无单价时标记为“不计价”；
- 自定义装备写入 item instance/manual overrides，不伪造内容模板引用。

### 3.4 故事

“详情”改名为“故事”，包含：

- 角色名与头像；
- 外貌；
- 个性特征；
- 理想；
- 牵绊；
- 缺点；
- 背景故事；
- 私人笔记。

角色名是唯一阻断创建的故事字段，其余字段可以留空并在角色卡中继续编辑。

### 3.5 审核

审核页按以下顺序展示：

- 身份与等级；
- 规则自动授予；
- 玩家规则选择；
- 自定义内容；
- 属性与关键派生值；
- 装备预算提示；
- 未完成的阻断项。

只有规则要求的必选项、角色名和基本构筑缺失时阻断创建。装备超额、自定义法术和
故事字段留空不阻断。

## 4. 战役档案编辑

字段顺序调整为：

1. 类型
2. 标题
3. 标签
4. 摘要
5. 正文
6. 关联条目

标签紧接标题。关联条目使用搜索选择器：

- 支持标题、类型和标签过滤；
- 已选条目固定显示在搜索结果上方；
- 每个结果可打开现有浮动资料阅读器；
- 不把所有档案一次性铺成 CheckboxListTile 长列表。

附件上传未实现，因此移除“附件即将推出”占位。正文继续使用标题、段落和列表块，
但区块使用无嵌套卡片的 surface/list 结构。

## 5. DM 快捷操作

入口保留在战役聊天的 DM 工具区域，并按以下流程工作：

1. 选择一个或多个目标角色；
2. 选择操作；
3. 填写最少参数；
4. 预览结果；
5. 执行并发送结构化系统事件。

本轮操作：

- 伤害：输入正数伤害值，内部转换为负 delta；
- 治疗：输入正数治疗值；
- 给予物品：搜索本地资料条目，设置数量，可选择自定义物品；
- 给予状态：选择常见状态或输入自定义状态，填写来源、持续时间和可移除性；
- 快速掷骰：支持 `NdX + 修正`、优势/劣势和可选说明；
- 角色检定：沿用现有属性/豁免/技能代掷。

UI 不再要求用户输入带符号的 HP 数字。按钮直接表达“伤害”与“治疗”。

所有状态修改复用现有角色/Actor 业务操作，不直接修改 UI 缓存。成功后：

- 更新角色状态；
- 刷新头像生命环和角色卡；
- 写入 GameEvent 或现有 CampaignActor audit；
- 发送引用结构化事件的 system message。

部分批量操作失败时保留成功结果，并列出失败目标；不得显示笼统“操作失败”。

## 6. 战役卡片

战役列表卡片折叠态只显示：

- 战役头像/图标；
- 战役名；
- 最近消息或状态；
- 未读数；
- 展开按钮。

展开态使用同一卡片内部的无边框布局：

- 置顶主聊天室入口；
- 成员数、当前身份和最近活动；
- 私聊与小群快捷入口；
- DM 可见的紧凑管理命令。

不在卡片内嵌套 Card。主要入口使用 Filled/Tonal button，其他命令使用 IconButton
或 ListTile。移动端避免横向挤压，宽屏允许两列快捷区。

## 7. 设置页

固定信息架构：

1. 身份模式
2. 外观
3. 游戏与聊天
4. 服务器、账号与同步
5. 本地内容与存储
6. 关于

保留并确保持久化：

- Player/DM 客户端视图模式；
- 主题模式；
- Material seed color；
- 标准/中/高对比度；
- 界面密度；
- 连续消息是否隐藏重复头像；
- HP 警告阈值；
- 快捷骰预设；
- 默认角色卡区域；
- 自动登录；
- 默认服务器。

删除或隐藏：

- 没有实际消费者的设置；
- 同一能力的重复入口；
- 战役级权限开关；
- 未实现功能的预告项。

服务器、登录、自动登录、同步设备和同步状态必须集中在同一区域。

## 8. Material 3 约束

本轮相关页面执行 Material 3 审计：

- 颜色只使用 `ThemeData.colorScheme` 语义角色；
- 文字只使用 `ThemeData.textTheme`；
- 间距以 8dp 系统为主，允许 4dp 微调；
- 常规触控目标不小于 48dp；
- 卡片不嵌套卡片；
- 对话框只用于短决策，长表单使用全屏页或底部面板；
- 搜索使用 SearchBar/SearchAnchor 或语义等价组件；
- 单选模式使用 SegmentedButton，开关使用 SwitchListTile；
- 表单错误就地显示，异步结果使用 Snackbar；
- NavigationBar、NavigationRail 和内容宽度按现有断点自适应；
- 动画只用于展开、选择和页面状态变化，不添加装饰性动效；
- 输入栏在窄屏、键盘弹出和长临时身份名称下不得溢出。

## 9. 暂不暴露的能力

以下入口在真正实现前隐藏：

- 战役专属角色创建资料；
- 群文件上传；
- 档案附件；
- 无后端或无持久化行为的设置；
- 战斗/遭遇流程入口；
- 任何“即将推出”占位操作。

服务端旧遭遇代码不在本轮删除，但不得重新进入主产品路径。

## 10. 数据流

```text
Flutter UI
  -> Character builder / DM command draft
  -> Rule validation or operation validation
  -> CharacterController / CampaignEventDispatcher
  -> Character operations or CampaignActor runtime command API
  -> revision + immutable event/audit
  -> local cache refresh
  -> chat system message rendering
```

UI 不直接写 Prisma、Drift 表或 Actor sheet map。临时消息身份是唯一例外，但它写入
消息命令的结构化 `speakerSnapshot`，不是运行状态。

## 11. 测试与验收

### 自动测试

- 创建角色不再弹出资料来源选择；
- 一级角色规则法术列表不包含高环法术；
- 规则法术达到 maximum 后不能继续选择；
- 自定义法术不计入 maximum；
- 装备价格和数量正确换算，总价可超过建议上限；
- 超额不阻止创建；
- 故事字段正确保存；
- 临时身份发送一条消息后清除，Actor 数量不变；
- 服务端拒绝新建或恢复 temporary Actor；
- 档案标签位于标题后，关联搜索可过滤并保留选择；
- DM 伤害、治疗、物品和状态操作更新状态并生成事件；
- 玩家看不到 DM 快捷操作；
- 设置重启后保持；
- 相关页面在手机与宽屏测试尺寸无 overflow。

### 手工验收

- 使用私人资料包创建一级施法者，无法在规则区选择九环法术；
- 创建装备总价超过建议金币的角色，页面警示但允许完成；
- 临时身份发言后不出现在任何角色管理列表；
- DM 在聊天中完成伤害、治疗、给予物品和状态，角色卡与系统消息同步更新；
- 设置页面不再混杂账号、主题和资料包入口；
- 输入栏在 360px 宽度和软键盘状态下完整显示。
