# 战役聊天壳层 UI 重构设计

日期：2026-07-22
版本线：0.1
状态：已确认，待编写实现计划

## 目标

在不修改现有服务端聊天协议的前提下，重构战役聊天页的客户端壳层，使其在手机、横屏和桌面上都具备稳定、紧凑且符合 Material 3 的聊天体验。

本轮重点解决：

- 手机端输入栏头像裁切、消息遮挡和窄屏拥挤。
- 顶栏重复展示成员、身份、搜索等低频信息。
- 所有消息都靠左、事件卡横跨整屏导致的阅读层级不清。
- `ChatAvatar` 与 `CampaignAvatar` 两套生命环实现并存。
- `CampaignChatPage` 职责过多，消息、输入、弹层和工具调度耦合。
- 身份面板功能顺序与可见性缺少稳定规则。

## 产品原则

1. 聊天是战役默认入口，核心发送流程始终保持一步可达。
2. 高频操作留在输入栏附近，低频管理功能进入战役中心。
3. 信息只在最合适的位置出现一次，不重复展示。
4. 不增加新的跑团功能，仅整理现有能力。
5. 重构必须保留玩家本人、其他玩家、DM、旁白和临时身份的权限边界。

## 页面结构

聊天页固定为三个区域：顶栏、消息时间线和输入区。

### 顶栏

顶栏只承担导航：

- 左侧：返回。
- 中间：战役名称。
- 右侧：战役中心。

成员数量、当前发言身份和独立搜索按钮从顶栏移除。当前身份由输入栏头像表达；聊天搜索位于战役中心的“记录”页。连接异常时可在标题附近显示临时状态点，但不得长期占用文字副标题。

### 消息时间线

- 其他角色消息靠左，当前用户发送的消息靠右。
- 头像和角色名必须显示消息来源。
- 连续由同一角色发送的普通消息合并重复头像与名字。
- 说话使用气泡；动作使用弱底色和斜体。
- 旁白和系统事件居中，不使用普通角色气泡。
- 检定请求、骰点和物品变化使用紧凑事件卡，不横跨整个桌面宽度。
- 普通气泡设置响应式最大宽度，长消息正常换行。
- 时间仅在明显时间间隔或日期变化时显示。
- 点击角色头像统一进入完整角色卡；本人可编辑自己，其他玩家只读，战役 owner/manager 可编辑任意战役 Actor。

### 输入区

输入区保持单行：

`身份头像 | 说/做模式 | 输入框 | 发送`

- 视觉头像为 32px，外层点击目标为 48px。
- 生命环必须包含在头像视觉边界内，不得被按钮裁切或与头像重叠。
- 说/做模式使用两个紧凑图标，不显示常驻文字；Tooltip 与 Semantics 提供名称。
- 输入框和发送按钮随可用宽度收缩，但不得低于可用的最小触控尺寸。
- Composer 统一处理 `SafeArea`、键盘 inset 和自身实际高度。
- 消息时间线按 Composer 实际高度预留底部空间，最后一条消息始终可见。
- 发送失败保留输入内容，并给出明确的失败与重试反馈。

## 身份与工具面板

保留现有 Material 3 底部面板和宫格结构，只做轻量优化：

- 面板标题改为当前身份名称。
- 顶部展示头像、角色类型和生命状态，提供身份切换入口。
- 第一组为高频操作：角色卡、HP/状态、骰点、角色动作。
- 第二组为战役工具：资料条目、战役记录、线索、地点、群文件。
- DM 专属追加代掷检定和临时身份。
- 不可用功能直接隐藏，不显示灰色占位。
- 手机使用三列宫格；宽屏最多四列，并设置合理最大宽度。
- 保留当前视觉基调，不进行推倒式重绘。

## 组件与代码边界

`CampaignChatPage` 只保留页面生命周期、控制器协调和动作路由。具体 UI 拆分为可独立测试的组件：

- `CampaignChatTimeline`：消息分组、左右对齐、时间分隔和滚动定位。
- `CampaignChatComposer`：身份头像、模式选择、输入、发送和键盘适配。
- `CampaignChatToolSheet`：身份摘要、能力分组和权限可见性。
- 事件组件：旁白、系统、检定请求、骰点和规则动作。
- 统一 `CampaignAvatar`：头像图片、首字母、生命环、倒地状态和无障碍说明。

删除 `ChatAvatar` 的重复实现，所有战役列表、角色目录、消息气泡和 Composer 复用统一头像组件。权限判断由页面组装成明确 capability 后传给展示组件，子组件不自行读取全局 DM/Player 模式。

本轮只清理与聊天壳层直接相关的冗余代码，不扩展到角色详情、创建向导、资料库或设置页的大规模重构。

## 状态与错误处理

- 初次加载显示居中进度状态。
- 加载历史失败使用非阻塞横幅并保留重试。
- 实时连接中断不得清空本地消息；顶栏显示轻量状态提示。
- 发送中只锁定当前发送操作，不禁用浏览历史和打开角色卡。
- 发送失败恢复可编辑状态并保留草稿。
- 身份失效时回退到服务端允许的身份，不伪造本地发言来源。

## 响应式规则

- 必测尺寸：360x800、390x844、1280x720。
- 手机维持单列聊天；桌面不引入三栏工作台。
- 消息区设置阅读宽度和气泡最大宽度，不让内容贴满宽屏。
- 横屏时 Composer 仍保持单行，工具面板允许内部滚动。
- 页面不得依靠浏览器文档滚动承载 Scaffold；滚动只发生在消息列表或弹层内部。

## Material 3 与无障碍

- 颜色统一来自 `ColorScheme`；生命状态使用语义颜色映射，并保证明暗主题可辨认。
- 卡片半径不超过 8px，避免层层嵌套卡片。
- 所有图标按钮提供 Tooltip 和 Semantics。
- “说”“做”、当前身份、生命状态和发送状态均可被辅助技术识别。
- 视觉尺寸可以紧凑，但交互目标保持至少 48x48px。

## 验收标准

1. 三个目标尺寸均无 `RenderFlex`、裁切、溢出或输入栏遮挡。
2. 键盘打开后，输入框和最后一条消息仍可见。
3. 自己、他人、动作、旁白、系统、骰点和检定请求具有稳定且不同的视觉结构。
4. 连续消息分组不丢失发言者来源。
5. 未知 HP、健康、受伤、濒危和倒地头像均正确渲染。
6. 玩家、DM、旁白和临时身份只看到有权限使用的工具。
7. 头像进入角色卡的编辑权限符合服务端战役 membership。
8. 发送失败不会丢失文本。
9. Flutter analyze、相关 widget 测试、全量测试和 Web release 构建通过。

## 后续开发顺序

本轮完成后按以下顺序继续：

1. 重构角色卡与角色创建向导，提升规则信息层级和操作效率。
2. 统一全局 Material 3 视觉规范，包括页面宽度、间距、颜色、弹层和空状态。

这两项各自建立独立设计与实现计划，不与聊天壳层重构同时展开。

## 非目标

- 不新增地图、战斗工作台或桌面三栏聊天布局。
- 不修改聊天消息协议或新增服务端实体。
- 不重做现有头像工具面板的整体视觉风格。
- 不在本轮重构角色卡、创建向导、资料库和设置页。
