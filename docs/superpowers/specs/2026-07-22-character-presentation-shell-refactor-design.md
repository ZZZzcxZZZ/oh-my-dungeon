# 0.1 角色呈现壳层重构设计

## 目标

在不新增规则、不改变资料包格式和保存协议的前提下，将角色卡与标准创建向导中的响应式页面壳层从业务页面中拆出，并修复宽窄屏导航密度不一致的问题。

## 当前问题

- `character_detail_page.dart` 与 `character_editor_page.dart` 均超过 3300 行，页面导航、业务状态、规则投影和具体面板没有清晰边界。
- 角色卡在所有宽度都使用 8 项横向标签；手机可滚动但扫描成本高，桌面又没有利用横向空间。
- 标准创建向导将 NavigationRail、手机步骤选择器、底部动作栏和规则选择状态写在同一个 State 中，后续调整 UI 容易影响规则逻辑。
- 多处重复使用页面最大宽度、表面颜色、分隔线和安全区，但没有稳定的呈现层组件。

## 设计

### 角色卡壳层

新增 `CharacterSheetShell` 与 `CharacterSheetDestination`：

- 宿主只传标题、头部、操作按钮、目标列表和初始目标 ID。
- 600px 以下保留可横向滚动的 Material 3 TabBar，确保现有手势和测试契约不变。
- 900px 以上改用可扩展 NavigationRail，内容区限制到舒适阅读宽度。
- TabController、选中状态和 ID 到索引的映射全部由壳层管理。
- 具体总览、属性、动作、法术、装备、资源、特性和角色资料面板仍由原页面创建，不迁移业务状态。

### 创建向导壳层

新增 `CharacterBuilderShell` 与 `CharacterBuilderDestination`：

- 宿主传入当前步骤、可见步骤、编辑区、摘要区和底部动作区。
- 手机使用紧凑步骤选择器与进度；桌面使用扩展 NavigationRail、编辑区和固定摘要列。
- 壳层不读取职业、法术、装备或规则选择，不决定步骤是否可见。
- 规则选择、推荐值、创建校验和最终草稿仍留在 `_StandardBuildPageState`。

## 边界

- 本轮不改变 2024 规则计算、自动授予、子职业或升级队列。
- 本轮不重写角色卡八个业务面板。
- 本轮不做全局 ThemeData 重构；全局 Material 3 统一另立计划。
- 不修改服务端、同步协议或资料包结构。

## 验收

- 手机 360x800、390x844 与桌面 1280x720 无布局溢出。
- 角色卡窄屏保留标签导航，宽屏使用 NavigationRail；初始标签 ID 继续生效。
- 创建向导窄屏和宽屏仍可选择所有可见步骤，底部上一页、下一页和创建逻辑不变。
- 角色卡运行时修改、装备、法术、资源和人物资料测试无回归。
- `flutter analyze`、角色相关测试、Flutter 全量测试和 Web release 构建通过。
