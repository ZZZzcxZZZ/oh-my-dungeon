# v0.2 账号、服务器、双模式执行计划

更新时间：2026-07-09

## 目标

用户可以在自托管服务器上注册、登录，并让客户端按服务器 profile 隔离登录状态；Player/DM 模式从纯本地工作台偏好，逐步接入登录用户偏好。

## 不做事项

- 不实现 Campaign。
- 不实现 Session。
- 不继续扩展 `/api/rooms`。
- 不实现 WebSocket。
- 不实现完整 Server Admin 控制台。

## 服务端任务

1. Auth 数据模型。
   - User。
   - ServerAdmin。
   - RefreshToken。
2. 密码哈希服务。
   - 注册时保存 passwordHash。
   - 登录时验证密码。
3. 注册 API。
   - `POST /api/auth/register`。
   - 首次注册用户成为 ServerAdmin owner。
   - 注册开关关闭时拒绝。
4. 登录 API。
   - `POST /api/auth/login`。
   - 返回 access token 和 refresh token。
5. 当前用户 API。
   - `GET /api/auth/me`。
6. Refresh / Logout。
   - `POST /api/auth/refresh`。
   - `POST /api/auth/logout`。
7. Server settings API。
   - `GET /api/server-settings`。
   - `PATCH /api/server-settings`。

## 客户端任务

1. 按 server profile 保存 auth token。
2. 登录/注册页面。
3. 当前用户状态显示。
4. 退出登录。
5. 模式切换保留在设置中，并预留同步用户偏好的入口。

## 测试策略

- AuthService 单元测试覆盖注册、重复用户名、首次 owner。
- AuthController e2e 覆盖 register/login/me。
- 客户端 store 测试覆盖按服务器隔离 token。
- 登录/注册 widget test 覆盖主要 UI 流程。
