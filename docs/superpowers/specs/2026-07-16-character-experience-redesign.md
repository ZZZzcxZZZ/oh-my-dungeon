# 角色创建、升级与角色卡体验重构规格

## 目标

把现有角色模块重构为一个离线优先、规则驱动且允许随时快速修改的 D&D 2024 数字角色卡。创建和升级采用《博德之门 3》式的“只处理当前必要选择”流程；日常管理采用 D&D Beyond 式的角色卡内直接编辑；信息层级参考 2024 官方电子角色卡，但全部使用 Flutter Material 3 组件和本项目视觉语言。

本轮不复制商业产品的商标、美术或专有文案。所有规则内容继续来自用户本地导入的资料包，角色创建、升级和管理均可离线完成。

## 参考原则

- 《博德之门 3》升级界面把固定增长自动应用，只把子职、专长、属性和法术等必要决策展示为待完成步骤；存在未完成选择时不能确认升级。
- D&D Beyond 2024 创建顺序采用“职业、背景、物种、属性、装备”，并允许在角色卡中直接添加临时物品、额外专长和自定义动作。
- 2024 官方电子角色卡优先展示名称、职业等级、背景、物种、生命值、护甲等级、先攻、速度、熟练加值、属性和技能；特性、法术、装备和背景故事位于次级区域。

参考资料：

- [BG3 升级流程](https://eip.gg/bg3/guides/how-to-level-up/)
- [D&D Beyond 2024 工具更新](https://www.dndbeyond.com/changelog/)
- [D&D Beyond 角色卡改版](https://www.dndbeyond.com/posts/262-the-character-sheet-revamp-is-live-now)
- [D&D 2024 官方角色卡](https://media.dndbeyond.com/compendium-images/phb/downloads/DnD_2024_Character-Sheet.pdf)

## 核心设计原则

1. 规则是默认答案。固定授予、数值增长、法术位、资源和推荐选项由规则引擎自动计算。
2. 用户只处理必要选择。创建与升级页面不展示与当前角色无关的步骤。
3. 自动结果与手动编辑并存。手动添加、隐藏或替换通过覆盖层表达，不破坏规则来源。
4. 角色卡是日常工作区。除初次创建和升级外，玩家不必返回完整构建器才能修改角色。
5. 高频操作不超过两次点击。HP、状态、资源、装备数量、准备法术和笔记均可在当前栏目直接修改。
6. 服务器不是角色模块依赖。只有战役聊天室和战役协作需要连接服务器。

## 数据模型

现有 `CharacterSheet.data` 保持向后兼容，并增加以下稳定结构：

```json
{
  "profile": {
    "alignment": "",
    "appearance": "",
    "personality": "",
    "ideals": "",
    "bonds": "",
    "flaws": "",
    "backstory": "",
    "languages": []
  },
  "manualOverrides": {
    "features": {
      "addedEntryIds": [],
      "hiddenGrantKeys": [],
      "custom": []
    },
    "spells": {
      "addedEntryIds": [],
      "removedEntryIds": [],
      "preparedEntryIds": [],
      "custom": []
    },
    "actions": {
      "custom": []
    }
  }
}
```

### 覆盖层规则

- 自动特性由 `{sourceEntryId}#{grantId}` 唯一标识。
- 隐藏自动特性只把稳定键写入 `hiddenGrantKeys`，不删除 `resolvedGrants`。
- 手动资料条目写入 `addedEntryIds`，自定义无资料条目内容写入 `custom`。
- 法术最终集合为“规则授予与规则选择 + 手动添加 - 手动移除”。准备状态独立存储，不改变已知法术。
- 装备继续以 `inventory` 为角色持有物品的事实来源。每个物品拥有稳定实例 ID、可选资料条目 ID、名称、数量、装备状态、同调状态、消耗品标记和备注。
- 自动派生快照可随资料包升级重算；用户覆盖和运行时状态必须保留。

## 创建流程

### 入口

新建角色提供两个明确入口：

- `快速创建`：自动采用资料规则中的有效推荐项，玩家主要确认职业、等级和姓名。
- `引导创建`：逐步完成所有必要选择，允许替换推荐项。

### 引导顺序

基础顺序为：

1. 职业与等级
2. 背景
3. 物种
4. 属性
5. 熟练与语言
6. 装备
7. 法术
8. 身份与故事
9. 确认

实际步骤由规则选择动态生成。没有法术、额外熟练或语言选择时，对应步骤不出现。每一步显示：当前选择、自动获得内容、资料来源、有效推荐以及仍需完成的数量。

### 自动化

- 固定特性、生命值、速度、护甲基础值、豁免熟练、法术位和职业资源自动计算。
- `recommendedEntryIds` 在满足过滤条件时自动预选。
- 快速创建会采用推荐属性方案、技能、起始装备和法术；缺少推荐时采用确定性的第一个有效组合，并在确认页标记为“自动选择”。
- 规则缺失或引用失效时只阻止相关步骤，不丢失已经完成的选择。
- 确认页展示最终角色摘要、自动选择清单和仍存在的规则警告。

## 升级流程

升级采用独立的 `CharacterUpgradeDraft`，在最终确认前不修改角色。

### 状态机

```text
选择目标等级
  -> 计算固定变化
  -> 生成必要选择步骤
  -> 完成子职/专长/属性/熟练/法术选择
  -> 审核变化
  -> 原子应用
```

每个步骤具有 `pending`、`complete` 或 `blocked` 状态。仅当所有必要步骤为 `complete` 时启用“完成升级”。关闭升级页面会放弃草稿，原角色不变。

### 页面结构

- 顶部显示“当前等级 -> 目标等级”和完成进度。
- 左侧或移动端顶部使用步骤导航，只显示本次升级产生的步骤。
- 主区域显示当前步骤的候选项、推荐项和资料详情。
- 固定摘要持续显示新增 HP、熟练加值、法术位、资源和自动获得特性。
- 最终审核按“自动获得”“玩家选择”“数值变化”分组。

单次跨多级升级按等级顺序生成步骤，避免高等级选择先于其前置选项。第一轮不提供多职业创建，但状态机和构建数据不得假设永远只有一个职业来源。

## 角色详情信息架构

角色详情缩减为六个目的明确的栏目：

1. `总览`：战斗核心数字、属性、豁免、技能、资源、状态和休息。
2. `动作`：武器攻击、法术动作、规则动作和自定义动作。
3. `法术`：施法数据、法术位、已知法术、准备状态和快速添加。
4. `装备`：持有物品、数量、装备、同调、消耗与货币。
5. `特性`：职业特性、物种特质、专长和手动特性。
6. `角色资料`：外貌、人格、理想、牵绊、缺点、背景故事、语言和私人笔记。

删除现有无明确用途的“详情”栏目；“状态”并入总览；“笔记”并入角色资料。

### 固定角色头部

所有栏目共享紧凑头部：头像、名称、职业与等级、物种、背景，以及 HP、AC、先攻、速度和熟练加值。移动端允许头部折叠为单行状态条，桌面端保持完整摘要。

### 快速编辑

- 每个栏目在标题栏提供上下文添加按钮，移动端同时提供小型 FAB。
- 特性：使用资料库搜索添加条目，或创建名称、说明和使用次数完整的自定义特性；自动特性支持隐藏并可撤销。
- 法术：搜索添加、移除手动法术、准备或取消准备；规则必得法术不能删除，只能隐藏显示。
- 装备：搜索资料库添加、创建自定义物品、增减数量、装备、卸下、同调、取消同调和删除。删除使用可撤销 Snackbar，不弹出阻塞式确认框。
- 动作：允许创建自定义名称、动作类型、命中公式、伤害公式和说明。
- 角色资料：字段原地编辑，停止输入 600 毫秒后自动保存，并显示“正在保存 / 已保存 / 保存失败”。保存失败时保留本地输入并允许重试。

所有列表项显示来源：职业等级、背景、物种、资料包、手动添加或自定义。点击资料来源可打开本地 Wiki 条目。

## 响应式 Material 3 布局

### 移动端

- 使用紧凑 `SliverAppBar` 角色头部和 `TabBar.secondary` 栏目导航。
- 内容为单列滚动布局。
- 添加和编辑使用 Material 3 底部操作表、`SearchAnchor`、`FilterChip`、`SwitchListTile` 和标准表单控件。

### 宽屏

- 使用页面内 `NavigationRail` 切换六个栏目。
- 角色头部位于内容顶部，核心摘要保持可见。
- 总览采用稳定的两至三列网格；列表详情使用主从布局。

### 视觉约束

- 颜色全部来自 `ColorScheme`，不为角色页面维护独立硬编码主题。
- 卡片圆角不超过 8 像素，不嵌套卡片。
- 页面区段使用无框分组和分隔线；卡片只用于角色列表项、重复条目和工具面板。
- 图标按钮使用 Material 图标并提供 tooltip；文字按钮只用于明确命令。
- 动态内容必须具有稳定尺寸约束，不能因状态标签、按钮或长名称导致布局跳动。

## 角色列表

角色页提供独立的 `舒适卡片` 与 `紧凑列表` 布局偏好，并持久化到客户端设置。

### 舒适卡片

- 移动端单列，宽屏使用最小宽度 340 像素的响应式网格。
- 展示头像、名称、职业等级、物种、背景、HP 进度、AC、先攻、被动察觉、主要职业资源和当前状态。
- 卡片提供打开、升级和更多菜单；HP 可直接增减。
- 升级可用时显示 Material `Badge`，但不使用动画干扰浏览。

### 紧凑列表

- 单行或双行展示名称、职业等级、HP、AC 和状态数量。
- 保留打开、升级和更多菜单，不展示次要资料。

布局切换使用 `SegmentedButton`，只影响角色页，不复用全局紧凑列表开关。

## 架构边界

新增职责应拆分为以下单元：

- `CharacterOverrideResolver`：合并规则结果和手动覆盖，输出角色最终特性、法术和动作。
- `CharacterUpgradePlanner`：对比当前与目标构建，生成升级步骤、变化摘要和阻塞原因。
- `CharacterQuickEditService`：生成不可变角色更新，保证运行时状态和无关字段不被覆盖。
- `CharacterProfile`、`CharacterManualOverrides` 和库存实例模型：负责 JSON 兼容解析与序列化。
- 创建与升级页面共享规则选择组件，但拥有独立页面状态。
- 角色详情拆分为头部、导航和六个栏目文件，避免继续扩大现有单文件。

领域服务不依赖 Flutter Widget、服务器 API 或具体数据库。Repository 仍负责本地保存与 Vault 同步队列。

## 兼容与迁移

- 缺少 `profile` 或 `manualOverrides` 的旧角色按空对象读取，不要求数据库迁移。
- 旧 `notes` 首次读取时显示为私人笔记；第一次保存角色资料后仍同步回 `notes`，保持服务端和 Actor 快照兼容。
- 旧装备项缺少实例 ID 时按角色 ID、原索引和条目内容生成稳定本地 ID。
- 打开角色时继续使用规则投影器重算派生内容，但不得覆盖 HP、状态、装备、货币、笔记和手动覆盖。
- DM Actor 角色卡复用相同只读解析模型；DM 快速编辑通过现有完整编辑权限写回 Actor 快照。

## 错误处理

- 资料条目在选择后消失：保留稳定 ID 和快照名称，标记“资料缺失”，允许替换或移除。
- 规则选择无有效候选：升级步骤进入 `blocked`，展示来源与缺失过滤条件，禁止应用升级。
- 本地保存失败：页面状态不回滚，显示重试操作；导航离开前提示仍有未保存字段。
- 跨设备同步冲突：运行时状态继续采用现有冲突策略；角色构建和覆盖层以完整角色修订为单位，不按数组位置合并。
- 自定义公式无效：表单原地校验并禁止保存，不执行任意脚本。

## 测试与验收

### 领域测试

- 自动授予、手动添加、手动隐藏和资料缺失能够得到确定的最终集合。
- 升级计划只生成本级必要步骤，按等级排序，并在未完成或阻塞时禁止应用。
- 应用升级保留 HP、临时 HP、状态、已消耗资源、装备、货币、角色资料和覆盖层。
- 旧角色 JSON 可无损读取并产生兼容默认值。

### Widget 测试

- 创建向导隐藏无关步骤，推荐项自动选中，缺失选择时不能确认。
- 升级向导显示固定增长、待处理选择和最终审核。
- 六个角色栏目在移动端和宽屏可访问，无横向溢出。
- 特性、法术、装备、动作和角色资料均可从当前栏目完成快速编辑。
- 角色列表两种布局可切换并持久化，大卡片无需进入详情即可查看核心数据。

### 发布验证

- `flutter analyze` 无问题。
- Flutter 全量测试通过。
- `flutter build web --release` 成功。
- 360x800、768x1024 和 1440x900 三种视口完成截图检查，无空白、遮挡、文字溢出或布局跳动。
- 本地预览可在无服务器状态下创建、升级、编辑并重新打开角色。

## 交付顺序

1. 覆盖层模型、解析器、升级计划器和兼容测试。
2. 角色详情六栏目、快速编辑和角色资料自动保存。
3. BG3 式升级向导及原子应用。
4. 创建向导动态步骤和快速创建自动推荐。
5. 角色列表舒适卡片、紧凑布局与偏好持久化。
6. DM Actor 复用、完整回归、响应式截图和文档同步。

每一步都必须形成可运行、可测试的增量，不允许以占位按钮或静态演示替代真实保存行为。
