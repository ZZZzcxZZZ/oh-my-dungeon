- [x] 资源具有 current、maximum 和 restoreOn。
- [x] 状态效果具有稳定 id、type、remaining 和 metadata。
- [x] 角色物品实例具有 id、数量、装备状态和模板引用。
- [ ] 打开同一角色的本地卡与战役卡，确认界面明确标注当前状态来源。

## 3. 统一查询接口

- [x] `character.get` 可读取完整角色与 resolved state。
- [x] `character.get_summary` 可读取有界摘要。
- [x] `character.list_events` 支持游标、类型和时间过滤。
- [x] `campaign.list_events` 支持有界事件读取。
- [x] 无权限访问由服务端策略校验，而不是依赖 UI 隐藏。
- [ ] 分别以角色所有者、普通战役成员、DM 和非成员身份检查返回内容。
- [ ] 确认列表页和目标选择器优先请求 summary，而非整张角色卡。

## 4. 统一修改接口

- [x] HP 调整通过 `character.adjust_hp`，并生成 revision 与事件。
- [x] 状态添加和移除通过统一业务操作。
- [x] 资源消耗和恢复通过统一业务操作。
- [x] 物品授予、消耗、装备、转移已由服务端业务接口实现。
- [x] 操作支持 requestId 幂等。
- [x] 操作支持 expectedRevision 乐观并发检查。
- [x] 服务端根据认证身份生成 actor，不信任调用方伪造 actorId。
- [ ] 使用相同 requestId 连续提交两次扣血，确认只生效一次。
- [ ] 使用旧 revision 修改状态，确认得到冲突且数据未被覆盖。
- [ ] 普通玩家尝试修改他人角色，确认被拒绝；DM 按既定权限可以管理战役角色。

## 10. 本轮验收结论

工程基线通过，角色状态操作、revision、幂等和事件记录已经形成可复用的
AI Ready 基础。当前仍不应接入具备写权限的 Agent：Flutter 条件字段、物品
操作接线、完整角色编辑审计和 Agent 授权边界尚未补齐。

战斗相关数据与工具不参与本清单，也不得因本规范而提前实现。
