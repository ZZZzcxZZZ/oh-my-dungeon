# 总体产品规划

## 1. 项目定位

D&D Table Tool 是一个面向 D&D 跑团过程的多端辅助平台，重点覆盖战役组织、房间协作、角色卡、掷骰、日志、资料库和 DM 控场。

它不是第一阶段就完整实现虚拟桌面地图的 VTT，也不是单纯角色卡工具。它的首要目标是让一个朋友团或社群可以自行部署服务器，并用 Flutter 客户端完成一次稳定的线上或线下辅助跑团。

## 2. 目标用户

### 2.1 DM

DM 需要创建战役、邀请玩家、管理资料库、开启跑团会话、发起检定请求、管理 NPC、遭遇、先攻队列、怪物 HP、状态效果和 DM 私密日志。

### 2.2 玩家

玩家需要加入战役、创建和维护角色、查看当前战役允许使用的资料库、参与聊天、响应检定请求、掷骰、维护 HP、法术位、装备、特性和状态。

### 2.3 服务器管理员

服务器管理员负责部署和维护自托管服务器，管理是否开放注册、服务器名称、基础内容包、备份恢复、版本升级和公共设置。服务器管理员不等同于战役 DM。

## 3. 客户端模式

客户端是一个 Flutter 应用，但明确分为两种工作模式。

### 3.1 Player Mode

主导航：

- 战役
- 角色
- 资料库
- 设置

Player Mode 的高频行为是进入已有战役、维护角色、查资料和参与跑团。加入战役不是高频导航项，入口放在战役列表页的主操作按钮或空状态引导里。

### 3.2 DM Mode

主导航：

- 战役
- 内容库
- 工具
- 设置

DM Mode 提供创建战役、开启跑团会话、管理成员、管理内容库、创建 NPC、创建遭遇和进入 DM 工作台的入口。

### 3.3 模式与权限的关系

客户端模式只影响导航和默认工作流，不代表真实权限。真实权限由服务端根据 CampaignMember 判断。一个用户可以在一个战役中是 DM，在另一个战役中是玩家。

## 4. 核心产品闭环

MVP 的核心闭环如下：

1. 服务器管理员部署服务器。
2. 用户在客户端添加服务器并注册登录。
3. DM 切换到 DM Mode，创建战役并生成邀请码。
4. 玩家切换到 Player Mode，通过邀请码加入战役。
5. 玩家创建角色并绑定到战役。
6. DM 开启跑团会话 Session。
7. 玩家和 DM 在桌面中聊天、掷骰、响应检定请求。
8. DM 管理当前遭遇、先攻、NPC、怪物 HP 和状态。
9. 系统将重要操作写入 JournalEntry，用于回顾、检索和审计。

## 5. 内容库系统

内容库是项目的一等能力。法术、装备、种族、职业、专长、特性、怪物、状态条件和房规都不应写死在客户端。

### 5.1 内容分层

- System Base Library：系统基础库，只读，所有战役可引用。
- User Library：用户个人库，用户自己导入或创建，可复用于多个战役。
- Campaign Library：战役扩展库，由 DM 管理，只对当前战役生效。
- Runtime Instances：运行时实例，例如角色学会的法术、背包里的物品、遭遇中的怪物。

### 5.2 修改规则

基础库不直接修改。DM 对基础内容的改动通过战役覆盖层实现：

- disable：在当前战役禁用某条基础内容。
- patch：在当前战役覆盖某些字段。
- derive：从基础内容派生一个新的战役变体。

### 5.3 内容模型

内容采用混合模型：

- 统一元信息：id、type、name、source、version、locale、tags、visibility。
- 关键结构化字段：用于搜索、筛选、角色卡引用和战斗辅助。
- 富文本描述：用于承载复杂规则、房规说明和叙事文本。
- 可选规则片段：后续逐步接入自动计算或快捷动作。

首版内容类型：

- 法术
- 装备和物品
- 特性和专长
- 怪物和 NPC 简表
- 状态条件

首版预留但不完整自动化：

- 种族
- 职业
- 子职业
- 背景
- 完整升级规则

## 6. 角色卡系统

角色卡采用中自动方案。

自动计算：

- 属性调整值
- 熟练加值
- 豁免加值
- 技能加值
- 先攻
- 被动察觉
- 基础 AC
- 最大 HP 建议值
- 法术攻击加值
- 法术豁免 DC

半自动提示：

- 种族、职业、背景带来的初始熟练项
- 初始特性
- 速度
- 语言
- 工具熟练
- 起始装备建议
- 职业资源模板

手动覆盖：

每个可计算字段都允许覆盖，并记录覆盖原因、更新时间和更新者。覆盖后 UI 应能显示来源，并支持恢复自动计算。

## 7. 跑团桌面

跑团桌面以协作为核心，不以地图为首要入口。

MVP 包含：

- 公共聊天
- 公开骰
- DM 暗骰
- DM 发起检定请求
- 在线成员
- 事件日志
- 当前遭遇简表
- 先攻队列
- 角色 HP 和状态快速更新

暂不进入 MVP：

- 地图战棋
- 战争迷雾
- 语音和视频
- 复杂私聊
- 消息编辑与撤回
- 高级宏系统

## 8. DM 控场

DM 控场应嵌入战役工作台和跑团桌面。

首版能力：

- 查看战役内所有角色
- 调整 HP、状态和资源
- 创建 NPC
- 创建遭遇
- 管理先攻队列
- 推进回合
- 隐藏怪物真实 HP 或部分信息
- 记录 DM 私密备注

## 9. 开源自托管定位

项目默认支持自托管。客户端不绑定单一中心服务器，用户可以添加、编辑、测试和切换多个服务器。

账号、token、缓存和偏好按服务器隔离。同一个用户名在不同服务器上不是同一个账号。
