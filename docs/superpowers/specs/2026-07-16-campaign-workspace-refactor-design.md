# 战役工作区重构设计

## 状态

本设计于 2026-07-16 完成产品方向确认。

目标是把战役重构为一个深度整合跑团能力的群聊工作区：进入即聊天，角色、规则、资料、地点、线索、文件、检定和未来战斗都围绕同一个战役上下文协作，而不是散落在互不相通的页面里。

## 产品目标

- 战役列表像群聊列表，点击战役直接进入聊天。
- 玩家使用唯一绑定角色参与战役，角色身份、头像、状态和规则动作自动进入聊天。
- DM 可以快速切换旁白、NPC、怪物、同伴和临时身份。
- 战役中心使用四个稳定领域组织全部功能：概览、队伍、档案、记录。
- DM 管理能力就地融合在相同页面中，不提供另一套独立后台。
- 服务端角色和权限是唯一权威来源，客户端模式不能授予战役权限。
- 为未来遭遇和战斗功能预留稳定接口，但本阶段不实现战斗引擎。

## 非目标

本次重构不实现：

- 战术地图、网格、Token 移动和视野。
- 完整战斗轮次、先攻追踪和自动伤害结算。
- 语音、视频和屏幕共享。
- 多聊天频道、论坛式子频道或通用插件运行时。
- 自动删除临时角色。
- 复杂的逐成员资料可见性规则。

## 核心原则

### 聊天优先

战役的默认入口始终是聊天，不要求创建 Session、开始场次或进入桌面。战役可以长期存在，所有成员随时阅读和发言。

### 权限简单但真实

用户只看到自己可以使用的操作。界面不展示禁用的 DM 功能，也不出现 Actor ID、权限策略、同步游标或 revision 等工程概念。

服务端对每个写入操作重新校验权限。客户端隐藏按钮只改善体验，不作为安全边界。

### 同一对象就地管理

玩家和 DM 使用相同的四个战役页面。DM 只是在角色、玩家、资料、线索和消息旁获得额外管理动作，不需要进入独立管理后台。

### 复用现有系统

保留现有 `CampaignMember`、`CampaignActor`、`CampaignChatMessage`、角色审计和战役同步基础。只补充唯一绑定、发言身份、角色生命周期、媒体资源和战役档案所需能力。

不新建一套与聊天重复的通用事件表。结构化聊天消息继续承担战役时间线，统计从消息、档案和角色审计数据中派生。

## 战役入口与模式

### 服务端成员身份

战役成员身份只有：

- `owner`：战役创建者，拥有全部权限。
- `dm`：由 owner 任命的协同主持人。
- `player`：普通玩家。
- `spectator`：只兼容存量数据，本阶段不提供新建入口。

### 客户端工作模式

设置中的 Player/DM 模式是应用工作区偏好，不是权限。

- owner 或 dm 在 Player 模式打开战役时，客户端显示一次“一键切换主持人模式”提示。
- 普通玩家即使切换到 DM 模式，仍然只拥有该战役的 player 权限。
- 战役创建入口只在 DM 模式显示。
- 服务端返回当前成员身份和能力集，客户端据此构建页面。

## 战役列表与创建

战役列表使用群聊列表结构，每个条目显示：

- 战役头像或名称首字母。
- 战役名称。
- 最后一条可见消息摘要。
- 最后活动时间。
- 未读数量。
- 当前在线成员头像叠放。
- 当前用户在该战役中的 owner、dm 或 player 身份提示。

点击条目直接进入聊天。加入战役保留在顶栏小入口，不占用底部导航。

创建战役只在 DM 模式显示，并使用简短向导：

1. 名称、头像和可选简介。
2. 确认创建者将成为 owner。
3. 创建成功后进入战役聊天，再从队伍页面邀请玩家。

不在创建向导中堆叠资料包、遭遇和高级权限配置。

## 玩家角色绑定

每名 player 在每个战役最多绑定一个有效角色。

### 未绑定状态

- 可以进入战役、阅读消息和发送场外发言。
- 输入栏左侧显示“绑定角色”入口。
- “说”“做”、角色检定、角色动作和角色资源操作不可用。

### 首次绑定

1. 玩家点击输入栏的绑定入口。
2. 从本地角色中选择一个角色。
3. 客户端上传角色头像和战役快照。
4. 服务端在一个事务中发布或更新 `CampaignActor`，并写入成员绑定。
5. 绑定完成后立即启用角色发言和规则动作。

不展示同步范围、可见性和冲突策略等高级选项。

### 更换与解除

- 玩家不能自行反复更换战役角色。
- owner/dm 可以在队伍页面解除或更换玩家绑定。
- 解除绑定不会删除角色快照或历史消息。
- 被解除的玩家恢复为未绑定状态。

## 发言身份

### 玩家

玩家可以在两个身份之间切换：

- 绑定角色：可使用“说”“做”、检定和角色动作。
- 场外身份：使用账号名称和账号头像发送 OOC 消息。

玩家不能使用其他玩家角色或 DM 的 NPC 发言。

### DM

DM 可以使用：

- `旁白 / DM`
- 账号场外身份
- 常驻 NPC、怪物和同伴
- 临时角色
- 明确开启的玩家角色临时代管

代管玩家角色时，消息必须显示“DM 代管”标记。完整角色编辑权与发言代管是两个不同能力，编辑角色不会自动允许静默冒充玩家。

当前发言身份保存在战役成员记录中，并跨设备恢复。

## 聊天界面

### 顶部

聊天顶部只显示：

- 返回
- 战役名称和简要在线状态
- 搜索
- 战役中心

不显示常驻角色信息条，也不在顶栏放大头像。

### 消息

支持以下消息类型：

- `ooc`：场外发言，使用账号身份。
- `say`：角色对话，使用聊天气泡。
- `action`：角色动作，使用斜体或动作表面。
- `roll`：结构化掷骰结果。
- `checkRequest`：DM 发起的检定请求。
- `system`：物品、状态、休息、资料发布等系统事件，使用加粗提示。
- `archivePublished`：资料、地点、线索或文件发布事件。
- 后续战斗功能可以增加受控的战斗事件类型。

每条角色消息保存发送时的：

- 发言者用户 ID
- CampaignActor ID
- 发言模式
- 显示名称快照
- 头像资源快照
- 可公开的角色状态分级快照
- 结构化事件数据

后续修改名称、头像或角色数据不会改变历史消息。

消息公开快照不得包含精确 HP、完整角色 sheet 或 DM 私有字段。精确状态只能通过 viewer-aware Actor 接口读取。

### 输入栏

输入栏结构固定为：

`当前身份头像与工具 | 小型说/做切换 | 输入框 | 发送图标`

当前身份头像取代原有独立 `+` 按钮。点击后打开底部快捷面板：

- 当前身份精确信息
- 打开角色卡
- 掷骰
- 技能检定
- HP 与状态
- 资料条目
- 记录线索
- 分享地点
- 群文件
- DM 身份切换
- 快速临时身份

工具按成员能力和当前上下文动态出现。界面不显示不可用的 DM 工具。

“说 / 做”使用紧凑分段控件。选择场外身份时隐藏该控件，输入框直接进入场外发言。

## 全局头像与生命环

所有玩家角色和具有生命数据的战役角色头像统一使用生命环。

### 显示规则

- 自己和 owner/dm：使用精确 HP 比例绘制圆环，快捷面板显示精确值。
- 其他玩家查看队友：服务端只返回健康分级，不返回精确 HP。
- 健康分级固定映射为健康、受伤、危险、倒地和未知，不使用精确比例。
- NPC 和怪物默认对玩家显示未知；DM 可以将其健康分级设为队伍可见。
- `maxHp` 缺失、为零、不适用或不可见时使用中性圆环。
- 0 HP 使用空的危险色圆环和倒地角标，保证状态可辨认。

消息名字旁不重复显示 HP 数字。

### 点击行为

- 点击自己的头像：显示精确状态并可进入角色卡。
- 点击队友头像：显示公开角色摘要和健康分级。
- DM 点击任意角色：显示完整战役角色摘要，并提供检定、状态、编辑和加入未来遭遇等操作。

## 头像上传与媒体资源

### 头像来源

- 账号头像：用于 OOC 发言。
- 本地角色头像：离线保存在客户端。
- 战役角色头像：本地角色绑定战役后自动上传。
- DM NPC、怪物和临时角色头像：保存为战役资源。

不提供独立“聊天头像”设置。聊天头像始终跟随当前发言身份。

### 上传流程

1. 用户选择拍照或本地图片。
2. 客户端显示方形裁剪和缩放。
3. 客户端生成适合头像使用的压缩图。
4. 服务端校验文件类型、尺寸和大小，并保存不可变媒体资源。
5. 更换头像会生成新的资源 ID，不覆盖旧文件。

历史消息引用不可变资源，因此旧消息头像不会改变。

### 存储边界

- 数据库存媒体元数据，不存大文件正文。
- 默认存储适配器使用服务器本地磁盘。
- 存储接口允许未来替换为 S3 或 MinIO，但本阶段不实现对象存储管理界面。
- 战役群文件与头像复用同一媒体服务，但使用不同 purpose 和大小限制。
- 媒体读取接口根据账号、战役成员身份和资源 purpose 校验访问。
- 被角色、账号、档案或历史消息引用的媒体资源不能删除。

## DM 角色生命周期

战役角色分为：

- 常驻：长期 NPC、怪物和同伴。
- 临时：聊天中快速创建的一次性或短期身份。
- 已归档：不再出现在默认切换器中，但保留数据和历史关联。

### 快速临时身份

聊天身份面板保留“快速临时身份”：

1. 只要求输入显示名称。
2. 可以选择性上传头像。
3. 在本地成为待发送草稿。
4. 首次发送消息时，服务端在一个事务中创建临时 CampaignActor 和消息。
5. 未发送的草稿不会污染服务器。

### 完整管理

完整管理位于 `战役中心 -> 队伍`，仅 DM 在相同页面看到：

- 最近使用
- 置顶身份
- 搜索
- 常驻、临时和已归档筛选
- 转为常驻
- 单个或批量归档
- 清理没有任何消息和关联的草稿
- 编辑头像与角色数据
- 切换为当前发言身份

不自动删除临时角色。归档始终保留历史消息、线索、地点和战斗引用。

## 战役中心

战役中心使用四个稳定领域。

### 概览

只显示高价值信息：

- 当前地点
- 当前进度
- 未处理线索
- 队伍危险状态
- 最近发布
- 最近关键事件

DM 在相同位置额外看到控场摘要、群体检定和遭遇准备入口。

### 队伍

统一显示：

- 玩家
- 玩家绑定角色
- 公开 NPC
- 在线状态
- 健康状态环

DM 就地获得：

- 邀请和管理成员
- 角色绑定
- 完整角色编辑
- 发起检定
- 状态修改
- 发言身份管理
- 临时角色归档

### 档案

资料、地点、线索和文件统一属于战役档案，通过页面内筛选切换：

- 全部
- 资料
- 地点
- 线索
- 文件

档案条目支持标签、公开状态、来源消息、关联角色、关联地点和相关条目。

DM 在相同页面创建、编辑、发布、隐藏和归档。玩家只看到已发布内容。

### 记录

记录页面通过标签切换：

- 聊天
- 事件
- 统计

聊天搜索支持发言者、日期、消息类型和附件筛选。事件显示检定、物品、状态、档案发布和未来战斗事件。统计从结构化消息和角色审计派生。

DM 在相同页面获得置顶、隐藏违规消息、导出和审计入口。

### 全局设置

只有以下低频操作保留在右上角更多菜单：

- 战役名称、封面和简介
- 所有权转移
- 战役归档
- 离开战役

## 服务端数据模型

### User 与 Campaign 扩展

- `User.avatarAssetId`：账号头像，用于 OOC 发言。
- `Campaign.avatarAssetId`：战役列表和战役中心头像。

### CampaignMember 扩展

- `boundActorId`：player 唯一绑定的战役角色。
- `activeSpeakerActorId`：owner/dm 当前发言角色。
- `speakerMode`：`account | narrator | actor | delegated`。
- `lastReadAt`：计算战役列表未读消息。

数据库约束保证同一个 CampaignActor 不能同时绑定给多个玩家。

### CampaignActor 扩展

- `lifecycle`：`persistent | temporary`。
- `status`：`active | archived`。
- `avatarAssetId`：不可变头像资源。
- `healthVisibility`：`managers | party`。
- 继续保留角色快照、revision、updatedBy 和审计记录。

### CampaignChatMessage 扩展

- 增加 `ooc` 和 `archivePublished` 类型。
- 增加 `speakerMode` 和代管标记。
- 头像快照改为不可变媒体资源引用。
- 保留 `eventData` 和 `actionSnapshot`。
- 增加服务端分页、搜索和筛选索引。

### CampaignArchiveEntry

统一承载档案条目：

- `kind`：`document | location | clue | file`
- `title`
- `summary`
- `bodyJson`
- `visibility`：本阶段只支持 `party | managers`
- `status`：`draft | published | archived`
- `sourceMessageId`
- `mediaAssetId`
- `createdBy / updatedBy`
- 时间戳和 revision

关联关系使用独立轻量链接表，连接档案条目、消息、角色和地点，不在正文中复制对象。

### MediaAsset

- 所有者用户和可选战役 ID
- purpose
- 存储键
- MIME 类型
- 文件大小
- 宽高
- 内容哈希
- 创建时间

媒体资源创建后不可原地修改。

账号、战役、Actor、档案和消息分别通过资源 ID 引用同一个媒体服务，不复制二进制文件。

## 权限能力

服务端战役视图返回成员身份和能力集。能力名由客户端内部使用，不显示给用户。

最低能力包括：

- 查看战役
- 发送 OOC
- 绑定初始角色
- 使用绑定角色发言
- 编辑自己的战役角色
- 查看队伍摘要
- 管理成员
- 管理任意角色
- 使用 DM 发言身份
- 发布档案
- 发起检定
- 管理消息
- 查看审计

角色读取也必须使用服务端投影：

- owner/dm：完整角色快照。
- 角色所有者：自己的完整快照。
- 其他玩家：公开摘要，不返回完整 sheet JSON 和精确 HP。

这将替换当前“所有战役成员都可读取完整 CampaignActor sheet JSON”的行为。

## 客户端模块

拆分当前大型聊天页面：

- `campaign_workspace`
  - 战役外壳、成员上下文、自适应导航。
- `campaign_chat`
  - 消息列表、消息组件、输入栏和搜索入口。
- `campaign_speaker`
  - 当前身份、身份切换、临时身份草稿。
- `campaign_party`
  - 玩家、角色、绑定和 DM 就地管理。
- `campaign_archive`
  - 资料、地点、线索和文件。
- `campaign_records`
  - 聊天搜索、事件和统计。
- `campaign_media`
  - 选择、裁剪、压缩、上传和缓存。
- `campaign_permissions`
  - 服务端能力集到界面可见性的映射。

角色、资料库和规则引擎保持独立，通过明确接口向战役模块提供快照、详情和动作。

未来战斗模块只能依赖 CampaignActor、结构化消息和档案关联接口，不直接依赖聊天页面组件。

## API 方向

保留现有战役和 Actor API，增加或收敛以下操作：

- 获取战役上下文：成员身份、能力、绑定和当前发言身份。
- 初次绑定角色：发布 Actor 与绑定事务。
- DM 更换或解除成员绑定。
- 设置当前 DM 发言身份。
- 发送消息，支持临时身份草稿的原子创建。
- 分页和筛选聊天记录。
- 档案 CRUD、发布和归档。
- 媒体上传、读取和删除未引用资源。
- viewer-aware 的队伍和 Actor 投影视图。

所有 DM 写入接口同时检查成员角色和对应能力。

## 离线与同步

- 本地角色、资料库和规则能力继续完全离线可用。
- 战役聊天和协作写入需要服务器。
- 已同步的战役角色、档案摘要和最近消息可以缓存供离线查看。
- 本地角色头像离线保存；绑定战役时自动上传远端副本。
- 私有资料包正文不因档案或头像功能上传。
- 战役档案只同步 DM 在战役中创建的独立内容和用户主动上传的文件。

## 错误处理

用户界面使用直接、可行动的提示：

- “请先绑定角色。”
- “该角色已由 DM 更新，请刷新后重试。”
- “图片太大，已自动压缩。”
- “没有权限执行此操作。”
- “临时角色创建失败，消息尚未发送。”

客户端不显示 HTTP 状态码、Prisma 错误、revision、cursor 或堆栈信息。

临时角色创建和首条消息发送必须在同一服务端事务中完成，任一步失败都不留下孤立角色。

## 迁移策略

1. 为现有 owner 成员补齐 `role = owner`。
2. 现有已发布 player Actor 不自动绑定；首次进入时根据唯一 ownerUserId 候选提供一键确认。
3. 一个玩家存在多个 player Actor 时不自动选择，由玩家选择一个，其余保留为未绑定战役角色并由 DM 处理。
4. 现有 NPC 默认为常驻、使用中。
5. 现有消息继续保留 URL 快照兼容读取，新消息使用媒体资源 ID。
6. 现有 CampaignContentEntry 迁移为 document 类型档案，不丢失 revision 和同步记录。
7. 旧 Session、Journal 和 Encounter 不重新接入主导航；只在后续迁移对应功能时读取。

## 测试策略

### 服务端

- owner、dm、player、spectator 权限矩阵。
- 客户端模式不能提升权限。
- 每名玩家每战役只能绑定一个角色。
- 玩家不能使用其他 Actor 发言。
- DM 代管消息必须带代管标记。
- 临时身份与首条消息原子创建。
- 归档角色不破坏历史消息。
- Actor 投影不会向其他玩家泄露完整 sheet 和精确 HP。
- 媒体类型、大小、战役成员访问和不可变性校验。
- 被历史消息或角色引用的媒体资源不能误删。
- 档案草稿、发布、隐藏和归档权限。
- 聊天分页、筛选和搜索。
- 未读数量只统计当前成员可见且晚于 `lastReadAt` 的消息。

### 客户端

- 未绑定、已绑定、OOC、DM 身份切换流程。
- 玩家和 DM 在相同页面看到正确动作。
- 普通玩家切换全局 DM 模式后仍不出现战役 DM 功能。
- 头像生命环的精确、分级、未知和倒地状态。
- 输入栏紧凑布局和窄屏不溢出。
- 四区导航在窄屏使用 NavigationBar，宽屏使用 NavigationRail。
- 战役列表显示最后消息、未读数量、在线成员和成员身份。
- 头像裁剪、压缩、失败重试和离线显示。
- 临时身份草稿未发送时不进入服务器列表。

### 端到端

- 玩家加入、绑定角色、上传头像、发言、响应检定。
- DM 创建临时身份、发言、转为常驻、归档。
- DM 在队伍页面编辑玩家角色后，玩家刷新得到新 revision。
- DM 发布地点和线索，聊天出现结构化发布消息，玩家可跳转查看。
- 历史消息在角色改名或换头像后保持原快照。

## 验收标准

- 打开战役直接进入聊天，不需要 Session。
- 战役列表具备最后消息和未读提示，交互行为符合群聊入口。
- 玩家每个战役只能绑定一个角色。
- 未绑定玩家可以旁听和 OOC，但不能角色发言或检定。
- 普通玩家不能通过客户端模式获得 DM 能力。
- DM 管理能力融合在概览、队伍、档案和记录页面中。
- 聊天顶部不再有占空间的角色栏。
- 输入栏头像统一承担身份、状态和工具入口。
- 全局角色头像使用生命环，名字旁不重复显示 HP。
- 角色和账号支持头像上传，历史消息头像保持不变。
- DM 可以快速创建临时身份，并在战役中心集中归档和清理。
- 其他玩家看不到完整角色快照和精确 HP。
- 资料、地点、线索和文件统一进入档案系统并可从聊天跳转。
- 当前聊天页面被拆分为职责清晰、可独立测试的模块。
- 未来战斗功能可以复用 CampaignActor、结构化消息和档案关系，而不需要重写战役导航。

## 参考产品结论

- D&D Beyond：战役是角色、玩家和游戏记录的中心。
- Foundry VTT：Actor 是玩家角色、NPC 和怪物的统一抽象，角色与文档权限分层。
- Roll20：角色、Handout 和聊天档案共同组成长期游戏资料。
- Discord/QQ群聊：聊天是最低门槛入口，搜索、文件、置顶和成员信息围绕群聊存在。

本项目采用这些产品的边界思想，但保持 Flutter Material 3、自托管、离线优先和中文网络跑团的简明交互。
